# R4-C0 Gate 1：初始过分割可行性（2026-10-30）

预注册：`946fb761a32d1016ca4cc4d01a915510da3eb007`，只运行一次。
代码：`experiments/R4C0/r4c0_gate1_one.py`。结果：`experiments/R4C0/gate1/gate1_summary.json`，逐图文件为 `gate1/<图>_<候选>.json`。初始区域和合并序列只保存在本地：`runs/r4c0/gate1/*.npz`。
输入是冻结的 M1 / M2 / B2 权重在 10 幅训练图上的推理结果（样本内，`runs/r4c0/pred/`），没有训练。**Oracle A 和 Oracle B 都读取了官方实例，是上限，不是模型成绩。**

|---|---|---|---|---|---|---|---|

两条停止条件都没有触发：所有候选的 Oracle A ≥ 0.90，Oracle B ≥ 0.80。计算量远低于限制（预注册上限为每图 15 分钟、12 GB、40 万个区域）。

## 3. 解读

- **初始区域基本保住了 6–20 px 的地质结构。** 6–10 px 组只有 10–12% 的实例在初始区域中就已经和邻居混在一起，10–20 px 组约 1%。所以，对这两组来说，"区域图能否恢复"取决于合并做得好不好，而不是初始区域本身。
- **3–6 px 组从一开始就有 55–70% 是混合的。** 这与 R4-B1T Gate 3 一致：这些单元的像素大多压在墨线上。区域图路线对这一组的上限很低，按预注册单独报告。
- **Oracle B 与 Oracle A 很接近**（6–20 px 组相差 0.01–0.02）。这说明"每个区域只用一次、只能合并相邻区域"这两个约束带来的损失很小。
- **需要注意乐观偏差：** 这些都是在训练图上的样本内预测，边界比在新图上清晰，所以上限可能偏高。Gate 3 在开发图上检验。

## 4. 候选选择（Gate 2 规则）

按预注册，在合格候选中选 6–20 px 组 Oracle B 最高的：**B2（0.957）**，高于 M1 和 M2（各 0.948），差距超过 0.005 的平局阈值。

需要说明：B2 在 R4-B2 中用硬阈值连通分量重建时失败了。这里用的是它的边概率作为过分割和合并的输入，两者是不同的重建方式。
