## 3. 解读

1. **净恢复 424 个，与你的计算一致。** 新恢复 229 + 297 = 526 个，新丢失 45 + 57 = 102 个。
2. **最主要的修图负担是伪碎片，规模比"新增过分割的小实例"大得多。** 相对 M2_hybrid，RAG_B 多出 388（13014）和 790（15076）个明显伪碎片，合计约 1,180 个，而净恢复是 424 个。也就是说，每多恢复 1 个地质单元，大约要多处理 2–3 个碎片。碎片合并通常比重新描绘一条漏掉的地层容易，但这个比例需要人工验收来确认。
3. **不能用"删掉所有小区域"来简单清理。** RAG_B 产生的小于 200 px 区域中，有 199 / 284 个是真实的小地质实例（M2_hybrid 只有 26 / 30）。按面积一刀切，会把刚恢复的窄地层再删掉。
4. **伪边界主要落在印刷墨线上。** 87–92% 的伪边界在墨线 1 px 内，可能来自等高线、文字、断层或花纹。13014 上伪边界增加了 2,377 px，15076 上只增加 385 px。需要在验收包的 FALSE_BOUNDARY 窗口中逐一判断是哪一类。你提到的 `false_boundary_share`（0.0028 → 0.0134）用的是另一种口径（落在"远离任何官方界线的墨线"1 px 内的比例），两者结论一致。
5. **拓扑没有问题：** 三种方案的多边形都 100% 有效，共享边界由同一张区域图推出，导出后重新读取一致。

## 4. 人工验收方法（提议，尚未执行）

- **记录表** `gis_qa_record_template.csv` 的字段：图幅、窗口或范围、方案、操作类型（合并 / 拆分 / 重绘 / 删除 / 改属性 / 无）、次数、耗时（分钟）、原因、操作员、日期、备注。
- **估算方法：** 同一操作员在同一批窗口上分别修正 M2_hybrid 和 RAG_B 的结果，直到与官方参考一致，记录操作次数和耗时，两种方案的顺序随机。由窗口内的耗时，按每类窗口在全图中的出现频率外推到整幅图，并给出范围，不给单一数字。
- **限制：** 72 个窗口是按类别分层抽的，不是全图均匀抽样，外推时必须加权。本报告的所有数字都是算法统计，不是人工时间。
