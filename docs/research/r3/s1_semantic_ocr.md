# R3-S1：地层代号识别与语义赋值 PoC（2026-10-28）

分支 `research/r3-semantic-ocr`，基于冻结提交 `6907eb2`（评价冻结记录见 `experiments/R3/freeze/README.md`）。
只用开发图 08004 榛名山、08001 坂城。封存图 08011、08021 没有读取。
所有分数都是 `UNCALIBRATED`。没有人工审核过的 OCR 真值，所以 OCR 部分是**初步结果**。

## 1. 环境与依赖

- macOS（`uname -s = Darwin`），Python 3.11.15。完整依赖见 `experiments/R3/freeze/pip_freeze_r3.txt`。
- **Tesseract 5.5.2**（Homebrew，Apache-2.0），语言包 `eng`。
- **RapidOCR 3.4.5**（Apache-2.0），ONNX Runtime 1.23.2（MIT），模型为 PP-OCRv4 检测和识别（Apache-2.0）。
- **依赖冲突：** RapidOCR 会附带安装 `opencv-python 4.11`，它和项目锁定的 `opencv-contrib-python-headless 4.10.0.84` 冲突。我卸掉了前者，恢复锁定版本。之后 `pip check` 会报 rapidocr 缺少 `opencv-python`，但功能正常。
- **没有测 PaddleOCR：** 它在 Mac arm64 上安装较重。RapidOCR 用的就是同一套 PP-OCRv4 模型，可以作为代表。

## 2. 数据边界

- **预测脚本**（`s1_legend_ocr.py`、`s1_map_spot.py`、`s1_semantic.py`、`s1_ocr_lib.py`）只读原图、图廓和配准，以及 R1 的输出（色块框、类别图）。
- **评价脚本**（`s1_legend_ref.py`、`s1_spot_eval.py`、`s1_eval.py`）读取官方 xlsx 和真值，文件头标有 `EVALUATION ONLY`。
- **代号词表来自系统自己：** 图面代号匹配用的合法代号表，是系统从图例 OCR 读出来的，不是官方 xlsx。

## 3. 图例代号 OCR（文字定位已由色块框给定，这里只测字符识别）

**评价参照：** 每个检出的色块，取官方 RGB 最近（ΔE<10）且颜色不与其他单元重复的那个单元的代号。
同色组里的色块无法用颜色确定参照，所以**没有计分**：08004 有 6 个，即 {Mz, Sm, Jg, Hf} 和 {Ohf, Ic}；08001 有 2 个。
因此，“同色组色块的代号能否读对”这一项**本轮没有测到**。

| 引擎 | 08004 完全正确（共 30 个） | 08001 完全正确（共 36 个） |
|---|---|---|
| Tesseract psm7（单行） | 23（0.77） | 12（0.33） |
| Tesseract psm8（单词） | 1（0.03） | 0 |
| RapidOCR 仅识别 | 12（0.40） | 9（0.25） |
| RapidOCR 检测+识别 | 4（0.13） | 7（0.19） |
| Tesseract + 下标拆分 | 22（0.73） | 18（0.50） |
| **Tesseract + 下标拆分 + 大小写规则** | **23（0.77）** | **18（0.50）** |

- **“下标拆分”是什么：** 把代号里偏小、偏下的数字单独切出来，用数字白名单识别。08001 的代号大量带下标（A1–A5、O1–O3、M1–M3），这一步让正确数从 12 提高到 18。
- **典型错误：**
  - 下标没切开：`A3→As`、`A1→Ar`。
  - 字母混淆：`Yk→vk`、`Tr→oh`。
  - 漏读：`Om` 没读出来。
- **RapidOCR 在图例框上不如 Tesseract：** 它在 96×50 px 的短代号上经常输出空串或错字，比如 `0m`、`YK`。

## 4. 图面代号定位与识别

做法：在整张图上分块，用 RapidOCR 检测文字框，每个框分别用 RapidOCR 和 Tesseract 识别，再用词表匹配（允许完全一致，或长度≥2 时差 1 个字符）。

| | 08004 | 08001 |
|---|---|---|
| 检测到的文字框 | 266 | 约 470 |
| 匹配到词表（RapidOCR 识别） | 38 | 41 |
| 其中代号正确（与官方单元一致） | **30（0.79）** | **25（0.61）** |
| 有正确锚点的单元 / 有代号的单元 | 12 / 40 | 11 / 44 |
| 有正确锚点的实例 / 全部实例 | 24 / 515 | 25 / 830 |
| 这些实例覆盖的面积 | 45.1% | 12.1% |
| 匹配到词表（Tesseract 识别） | 46，正确 19（0.41） | 92，正确 23（0.25） |

- **RapidOCR 适合图面：** 用它识别图面代号比 Tesseract 准（0.79 / 0.61 对 0.41 / 0.25）。
- **覆盖率低：** 只有约 5% 的实例拿到了锚点。
- **没有测文字检测召回：** 没有图面文字位置的真值，所以检测召回**没有测**。
- **非代号文字基本被拦住：** 208–430 个文字框没有匹配到词表，判为 `NOT_A_CODE`，这些主要是地名、高程、坐标数字。
- **主要错误：** 下标丢失（`O→O1`、`M→M1`），以及形近代号混淆（`Cut→Cwt`、`Spf→Ohv`）。

## 5. 区域语义赋值（系统自主，评价时不做任何重映射）

候选区域就是 R1 类别图的连通块（08004 有 514 个，08001 有 897 个）。

| 方法 | 08004 像素准确率 / mIoU / IoU≥0.5 单元 | 08001 像素准确率 / mIoU / IoU≥0.5 单元 |
|---|---|---|
| A0：R1 自带 OCR（R2 基线） | 0.000 / 0.000 / 0 | 0.008 / 0.004 / 0 |
| A1：类别 → 色块代号（新的图例 OCR） | 0.601 / 0.362 / 16 | **0.426** / 0.202 / 8 |
| A2c：区域颜色 → 最近色块 | 0.597 / 0.374 / 15 | 0.334 / 0.163 / 7 |
| A2t：区域颜色 + 纹理 → 最近色块 | 0.642 / **0.401** / **17** | 0.366 / 0.172 / 8 |
| A3：A2t + 图面锚点 + 颜色自校正 | **0.655** / 0.353 / 15 | 0.352 / **0.204** / **11** |
| 对照：区域上限（匈牙利映射） | 0.819 / 0.454 | 0.699 / 0.361 |

| A3 的其他指标 | 08004 | 08001 |
|---|---|---|
| 未赋值比例 | 4.2% | 19.6% |
| 错误赋值比例 | 30.4% | 45.2% |

**各部分的增益：**
- **图例 OCR 贡献了绝大部分：** 准确率从 0 提高到 0.60 / 0.43。
- **区域级颜色和纹理：** 在 08004 上有帮助（A2t 比 A1：准确率 +0.04，mIoU +0.04），在 08001 上反而更差（A2t 比 A1：准确率 −0.06）。08001 的近色单元多，用一个区域的中位颜色去比色块颜色，不如 R1 逐像素随机森林的结果。
- **图面锚点（A3）结果不一致：**
  - 08004：A3 比 A2t 准确率 +0.013，但 mIoU −0.048。原因是锚点把颜色参考改成了少数大单元的图上实际颜色，小单元被归到这些大单元。
  - 08001：A3 的 mIoU 比 A1 略高（+0.002），IoU≥0.5 的单元多 3 个，但准确率更低，因为同色组区域没有锚点时会留空不赋值（19.6%）。
- **结论：** 图面锚点在目前的覆盖率（约 5% 的实例）下，还**不是可靠的增益**。

## 6. 同色异类

| 单元 | A1 IoU | A3 IoU |
|---|---|---|
| 08004 Ohf（全图最大的单元） | 0.700 | **0.918** |
| 08004 Sm | 0.441 | 0.058 |
| 08004 Mz / Jg / Hf / Ic | 0.000 / 0.000 / 0.000 / 0.026 | 0 |
| 08001 Ob | 0.362 | **0.954** |
| 08001 M3 / t1 / t2 / t3 | 约 0 | 约 0 |

- **大单元能区分了：** 同色组里面积最大的单元，靠图面锚点区分开了，IoU 达到 0.92 和 0.95。
- **小单元仍然没有：** 同组的其他小单元依然接近 0。08004 的 Sm 在 A1 里靠偶然的色块对应拿到 0.44，到 A3 被 Ohf 吞并。
- **原因：** 小单元在图面上没有读到代号锚点，只能靠颜色，而颜色本来就分不开它们。

## 7. 复核候选（A3）

| | 08004 | 08001 |
|---|---|---|
| 标记的区域 / 面积 | 188 / 22.3% | 594 / 39.6% |
| A3 错误像素中被标记覆盖的比例 | 9.2% | 37.3% |
| 标记区域中确实有问题的比例（错误或未赋值） | 31.2% | 91.9% |

- **08001 的 91.9% 不能直接看成复核有效：** 主要来自 `SAME_COLOUR_NO_ANCHOR`。系统主动留空不赋值的区域，按定义就算“有问题”，所以这个比例偏高。
- **几类信号的表现：**
  - `MULTI_CODE`（一个区域里有多个不同代号）：08004 有 4 个，覆盖 12.8% 的面积，但都不是真正的错误合并，而是锚点读错或落在边界附近。08001 有 1 个，是真正的合并。
  - `ANCHOR_COLOUR_CONFLICT`：08004 4 个，08001 11 个。
- **结论：** 目前的复核列表还不能把错误集中起来。08004 只抓到 9% 的错误。

## 8. 中国地质图定性检查（没有真值，不报告精度）

用同一套图例读取方法：
- **gm2（扫描图，33 个色块）：** Tesseract 在 33 个色块上都读出了内容，如 `Q`、`N`、`K`、`J`、`T`、`Td`，看起来像时代代号的首字母。下标和希腊字母基本丢失。
- **u1、u3（截图）：** 代号不在色块框里面。Tesseract 几乎没读出东西；RapidOCR 读出的是汉字和数字。这类图需要先定位色块旁边的说明文字，R1 的色块框内 OCR 方式不适用。

## 9. 失败样例与限制

- **同色组色块没有测：** 这些色块的 OCR 准确率没有测（见第 3 节）。要测，需要人工核对图例，大约需要 10 分钟。
- **图面文字检测召回没有测：** 缺少文字位置真值。
- **A3 会牺牲小单元：** 它的参数（`W_TEX=0.5`、`DE_GROUP=4`、`DE_CONFLICT=15`）是事先定的，没有调参，但 mIoU 在 08004 上下降，说明“用锚点重新估计颜色”这一步会伤到小单元。
- **评价问题（不影响语义指标）：** 冻结的线真值掩膜是在 200 dpi 下画的 1 px 线，再用最近邻缩小到 100 dpi，结果被打碎成约 1.5 万段。所有方法的线精度都因此被系统性低估。这是 R2 以来的共同问题，本轮没有改评分，见 S2 报告。

## 10. 复现

```bash
for n in 08004 08001; do y=$([ $n = 08004 ] && echo 2012 || echo 1980); I=data/raw/gsj/GSJ_MAP_G050_${n}_${y}_200dpi.jpg; R=runs/r2_gsj/$n/r1; O=runs/r3/$n
.venv/bin/python experiments/R3/s1_legend_ocr.py $I $R/r1_eval.json $O/legend_ocr.json
.venv/bin/python experiments/R3/s1_legend_ref.py $R/r1_eval.json data/raw/gsj/$n/$n.xlsx $O/legend_ocr.json $O/legend_ocr_score.json
.venv/bin/python experiments/R3/s1_map_spot.py $I runs/r2_gsj/$n/frame_reg.json $O/legend_ocr.json tess_sub_case $O/map_spot.json
.venv/bin/python experiments/R3/s1_spot_eval.py $R data/raw/gsj/$n/$n.xlsx runs/r2_gsj/$n/gt $O/map_spot.json $O/map_spot_score.json
.venv/bin/python experiments/R3/s1_semantic.py $I $R $O/legend_ocr.json $O/map_spot.json $O/s1 rapid
.venv/bin/python experiments/R3/s1_eval.py $R data/raw/gsj/$n/$n.xlsx runs/r2_gsj/$n/gt $O/s1 $O/s1_eval.json; done
```

**前置条件：** R2 的配准和 R1 运行目录，见 `docs/research/r2_real_map/gsj_r1_baseline.md`。
**结果 JSON：** `experiments/R3/results/<sheet>/`。
**可视化（本地，不提交）：** `runs/r3/<sheet>/vis_s1/`，包括原图局部、图例 OCR、图面代号锚点、A3 代号图、复核区域，由 `s1_vis.py` 生成。
