## 2. 本次新增的三项诊断

### D1：伪碎片与接触线的关系（修正 R4-C0.1b 中按"最小距离"归类的做法）

对 RAG 结果中小于 200 px 的区域，分为伪碎片（所属官方单元大 5 倍以上）和真实小单元（与官方实例 IoU ≥ 0.5），逐个统计：区域像素离官方交界线的距离分布、压在墨线上的比例、与局部交界线的夹角。

| 类别 | 训练图：伪碎片（1,684） | 训练图：真实小单元（398） | 暴露图：伪碎片（1,187） | 暴露图：真实小单元（477） |
|---|---|---|---|---|
| 墨带压在交界线上（≥ 80% 像素离交界 ≤ 1.5 px，且 ≥ 60% 在墨线上） | **978（58%）** | **62（16%）** | **807（68%）** | **125（26%）** |
| 沿交界的条带（≥ 50% 像素离交界 ≤ 2 px） | 606（36%） | 331（83%） | 361（30%） | 348（73%） |
| 只是挨着交界（最小距离 ≤ 2 px） | 88（5%） | 5 | 16 | 4 |
| 远离交界 | 12 | 0 | 3 | 0 |
| 狭长区域中与交界夹角 ≤ 20° 的比例 | 85% | 93% | 78% | 87% |
| 宽度 < 6 px 的个数 | **1,380** | **111** | **939** | **126** |

**结论：**
1. 您的批评成立。按严格口径，真正可以称为"墨带本身"的伪碎片占 58–68%，其余 30–36% 是沿交界的条带但不全是墨线，不能一概称为"印刷接触线"。
2. **"墨带"这个外观在两类之间重叠：** 真实小单元中也有 16–26% 落在同一类别。这正是您指出的结构性冲突。
3. **宽度小于 6 px 的区域中，伪碎片与真实小单元的数量比约为 7.5:1 到 12:1。** 所以"B2 在两侧都给出强边界"不能作为保护证据：伪碎片同样两侧都有强边界，而且数量多得多。

### D2：公共细分的复杂度与上限（训练图，M1 / M2 / B2 的初始过分割取交集）

| 方案 | 每图区域数（中位 / 最大） | 区域图边数最大 | 完整合并序列耗时最大 | Oracle A：3–6 / 6–10 / 10–20 px | Oracle B：3–6 / 6–10 |
|---|---|---|---|---|---|
| 只用 B2 | 1,916 / 6,617 | 17,567 | 0.2 s | 0.45 / 0.90 / 0.99 | 0.43 / 0.88 |
| M2 ∩ B2 | 19,458 / 47,285 | 105,044 | 1.0 s | 0.52 / 0.94 / 1.00 | 0.45 / 0.89 |
| M1 ∩ M2 ∩ B2 | 33,207 / 73,879 | 170,841 | 1.7 s | **0.59** / 0.96 / 1.00 | **0.50** / 0.90 |

（峰值内存 1.9 GB。Oracle A：允许用真值从初始区域中任意组合，忽略互斥；Oracle B：遵守区域不可分、只合并相邻区域。两者都是上限，不是成绩。）

**结论：**
1. **计算量不是问题：** 即使三种模型全部叠加，每幅图 7.4 万个区域，合并不到 2 秒，内存 2 GB。
2. **区域数会膨胀 10–18 倍，换来的上限提升有限：** 3–6 px 的 Oracle A 从 0.45 提高到 0.59，6–10 px 从 0.90 提高到 0.96。
3. **即使把现有三个模型的边界全部叠加，3–6 px 的上限也只有 0.59。** 这说明窄地层需要一个专门的候选生成器，单靠多叠几个现有模型解决不了。

### D3：现有 B2 对 3–6 px 地层两侧边界的覆盖

| | 训练图（44 个，样本内） | 暴露图（160 个） |
|---|---|---|
| 实例边界被 B2 覆盖的比例（中位数，1 个像素对容差） | 0.87 | 0.90 |
| 覆盖 ≥ 0.8 的实例 | 75% | 86% |
| 能明确识别两侧的实例 | 15 | 66 |
| 其中两侧都覆盖 ≥ 0.8 | 67% | 74% |

**结论：** B2 已经看到了大部分窄地层的两侧边界，线证据是存在的。3–6 px 失败的主要原因是：(a) 区域生成方式把这两条线之间的窄带切碎或吞掉；(b) 同样形态的伪碎片数量多出约一个数量级，难以区分。所以 ≤ 6 px 的关键是一个**能区分三类对象**的线对候选生成器，而不是更强的边界检测器。

## 3. 总体架构

```
L0 输入与归一化     栅格 / GeoTIFF → RGB、可选的分辨率与尺度估计、图框与图边空白（不读标签）
L1 证据生成器       E-LINE  线证据：B2 像素对边概率 → 线图（骨架、走向、连续性、端点）
                    E-REG   区域证据：M1 / M2 / B2 的边界概率与距离场
                    E-APP   外观证据：Lab 颜色、纹理统计（只在当前图幅内计算）
                    E-INK   印刷墨线证据：black-hat 墨线、墨带截面宽度
                    E-SYM   符号证据：OCR 地质代号、图例色块（预留接口）
L2 候选生成器       C-RAG    B2 过分割（现有）
                    C-PAIR   线对窄带候选（新，针对 ≤ 6 px 和部分 6–10 px）
                    C-SEED   M2 距离种子区域（现有，作为可选候选）
L3 公共细分         只把"保护级"候选的边界作为硬切割；其他候选只提供软证据（见 §6）
L4 统一区域图       每条边、每个区域都带有多类证据；决策状态 PROTECT / MERGE / UNCERTAIN；
                    带约束的层级合并
L5 拓扑与 GIS 输出   面、线（接触线、断层）、属性、决策状态、证据来源；
                    不读标签的导出（R4-C0.1b）
```

### 3.1 模块接口（数据约定）

| 对象 | 字段 |
|---|---|
| 像素对边证据 | `edge_right[y,x]`、`edge_down[y,x]` ∈ [0,1]；来源 id |
| 线图 | 节点（端点、交点、分叉点）；线段（像素链、长度、平均强度、方向序列、曲率）；来源 id |
| 候选区域 | 掩膜或区域 id；类型（RAG / PAIR / SEED）；预测宽度（内切宽度、线对间距）；生成器置信度；来源 id |
| 公共细分边 | 两侧区域 id；共享像素对数；各证据的统计量（边概率中位数、墨线占比等）；"由哪些生成器提出" |
| 区域记录 | 面积；预测宽度；狭长度；骨架长度；颜色均值 / 方差（非墨线像素）；墨线占比；OCR 代号锚点 |
| 决策 | 状态 ∈ {PROTECT, MERGE, UNCERTAIN}；触发的证据；证据所属的独立组 |
| GIS 输出 | `review_status`、`decision_state`、`evidence`（文本）、`width_est_px`、`conf`（未校准）；接触线的来源 |

## 4. 五类证据：能解决什么、何时不可靠、如何交叉验证

| 证据 | 能解决 | 不可靠的情况 | 独立组 |
|---|---|---|---|
| 地质线（接触线、断层、连续性、走向） | 窄层两侧界线；区分连续接触线与孤立线段；尖灭 | 等高线、道路、文字笔画也是线；B2 在一条墨带两侧各给一条边 | **G-NET**（来自 B2） |
| M1 / M2 / B2 的区域与边界预测 | 一般区域划分；距离场给出局部尺度 | 三者用相同的训练图和标签训练，错误高度相关；在中国图上会响应纹理 | **G-NET**（与上一项同组） |
| 颜色、纹理、花纹 | 宽单元的合并或分开；伪碎片与邻居同色 | 颜色相近的不同单元（约 14–30%）；晕渲、底纹、印刷色差；窄层干净像素很少 | **G-IMG**（直接来自图像，与网络独立） |
| 印刷墨线 | 识别墨带；估计印刷线宽 | 墨线也覆盖窄层；黑色岩性填色；与 B2 学到的东西相关 | **G-INK**（来自图像，但与 G-NET 部分相关） |
| 图例、代号、符号 | 同色不同单元；给区域赋属性；保护独立单元 | OCR 漏读或误读；代号可能不在单元内部；目前 GSJ 没有可用于训练的图例—单元对应 | **G-SYM**（与其他组独立） |
| 区域几何、邻接、拓扑 | 狭长、尖灭、孤立碎块；共享边界 | 由候选生成器派生，继承其错误 | 跟随生成它的组 |

**独立性按输入来源和失败模式判断，不按证据条数计数：**
- B2 的边与基于 B2 构造的线对候选属于同一组 G-NET。两者同时成立，只算一项证据。
- M1、M2 与 B2 用的是同一批训练图和同一套标签。它们之间的一致只能算"弱独立"，不能单独构成删除依据。
- 颜色（G-IMG）和 OCR 代号（G-SYM）与网络独立，是交叉验证的主要来源。

## 5. 尺度策略：预测阶段怎样估计尺度

正式推理时不能读取官方宽度，只能用预测出的量估计尺度。可用的估计方式有三种，分别适用于不同情况：

| 估计方式 | 定义 | 适用 | 局限 |
|---|---|---|---|
| 候选区域内切宽度 | 候选区域掩膜上的 2 ×（最大距离 − 0.5） | C-RAG、C-SEED 已形成的区域 | 区域还没形成（3–6 px 被吞掉）时得不到 |
| 线对间距 | 两条近似平行线段之间的垂直距离，沿走向取中位数 | C-PAIR 候选；还没有形成区域的窄带 | 依赖线图质量；弯曲处需要按局部走向测量 |
| M2 距离场 | 预测距离的局部极大值 × 2 | 有距离头时 | R4-B0 显示它对窄层会高估或低估 1–2 px |

**不按固定阈值切换：** 尺度作为一个连续量进入区域图的合并代价和决策状态，而不是在 6 px 或 10 px 处硬切换算法。下表只表示"随尺度变化，哪类证据的权重更高"：

| 预测尺度 | 主导证据 | 次要证据 | 主要风险 |
|---|---|---|---|
| ≤ 6 px | 线对（G-NET）+ 颜色（G-IMG，取窄带中线附近的像素） | 墨带宽度（G-INK）、代号（G-SYM） | 与墨带伪碎片外观相同，数量相差约 10 倍（D1） |
| 6–10 px | 区域候选 + 双侧边界强度 | 颜色 | 被大邻居吞并 |
| 10–20 px | 边界强度 + 颜色 | 形态 | 伪碎片与真实单元并存 |
| > 20 px | 区域内部一致性（颜色、纹理） | 代号、图例 | 等高线、文字把大单元切碎 |

## 6. 融合方式比较与首选方案

| | 方案 A：并行生成候选，统一区域图仲裁 | 方案 B：先 RAG，再迭代修正 | **方案 C：分级公共细分 + 统一区域图（首选）** |
|---|---|---|---|
| 做法 | 各生成器各自输出候选区域，再在区域图中处理重叠 | 用现有 RAG 得到主体，再由线追踪、窄层恢复等模块逐个修正 | 所有生成器的边界按置信度分级；只有"保护级"边界进入公共细分，其余作为边上的软证据；在一张区域图上统一做决策和合并 |
| 候选冲突 | 需要额外的重叠仲裁 | 由修正顺序隐式决定 | 在同一张图的同一组边上裁决 |
| 窄候选是否会在融合前就丢失 | 不会 | 会：RAG 已经把它吞掉的话，修正模块要从头重建 | 不会，前提是它被标为保护级 |
| 区域数 | 中 | 小 | 可控：D2 显示全部叠加会膨胀 10–18 倍，分级后只叠加少数保护级边界 |
| 共享边界一致性 | 需要后处理 | 每次修正后都要重新保证 | 由同一张区域图推出，天然一致 |
| 对现有代码的改动 | 中 | 小 | 中：需要给区域图的边加上来源和多类证据 |

**方案 C 目前只是优先研究的架构假设，实现尚未冻结。** 阶段一必须先证明两点：
1. 分级之后，区域数和计算量可控。D2 的上界是"全部叠加"：每图 7.4 万个区域、合并 2 秒、内存 2 GB。
2. 只把保护级边界作为硬切割，能保住窄候选，同时不引入大量伪碎片。

**防止公共细分产生海量伪碎片的措施：**
- 只有保护级候选的边界才进入公共细分，其他候选的边界只作为软证据记录在已有的边上；
- 同一组（例如 G-NET）内的多个生成器给出几乎重合的边界时，去重（例如 1 个像素对以内只保留一条）；
- 合并阶段照常吸收由软证据引起的小区域。

## 7. 决策状态与冲突规则

每个区域（尤其是窄候选和小区域）在合并前都有一个决策状态：

| 状态 | 进入条件 | 在合并中的含义 | GIS 输出 |
|---|---|---|---|
| **PROTECT** | 至少一项**已验证**的强证据支持它是独立单元（见下文） | 硬约束：常规合并不能吞并它；只有出现独立组的反证时，才降为 UNCERTAIN | 正常面 |
| **MERGE** | 来自**不同独立组**的证据一致支持它属于某个邻居，且没有保护证据 | 允许并入指定邻居 | 不单独输出 |
| **UNCERTAIN** | 证据冲突或不足 | 不做不可逆删除；按常规代价参与合并，但若被合并，记录"被并入"及原因 | 输出为需复核对象，或在合并后的面上标记疑似漏掉的窄层 |

**什么算"已验证的强证据"：** 只有在训练图和已暴露图上测过误报率、并且误报率低于事先定好的上限的证据，才能触发 PROTECT。按 D1 和 D3 的结果：
- **B2 的双侧强边界不能单独触发 PROTECT。** 宽度小于 6 px 的区域中，伪碎片和真实小单元的比例约为 7.5:1 到 12:1，而伪碎片同样两侧都有强边界。
- **可能的候选强证据：**
  - 窄带中线附近的颜色与两侧邻居都明显不同（G-IMG）；
  - 区域内有一个与邻居不同的 OCR 代号（G-SYM）；
  - 线对候选的间距明显大于当前图幅的印刷线宽（G-INK 与 G-NET 结合）。

  这些都要先在阶段一测出误报率，才能使用。

**冲突规则：**
1. **删除或合并一个高置信度的窄候选，需要至少两个不同独立组的证据同时支持。** 例如"颜色与邻居相同"（G-IMG）加上"墨线占比高、宽度接近印刷线宽"（G-INK）。G-NET 内部的多个信号只算一项。
2. **保护证据与合并证据冲突时，进入 UNCERTAIN，不做不可逆删除。**
3. **断层：** 断层两侧可以是同一单元，所以"有强线"不等于"两侧是不同单元"。区域图的边需要区分"接触线"和"断层"两种线。断层线输出为线要素，不强制切开区域。这需要线分类能力（现有 B2 不区分），在第一版中先作为 UNCERTAIN 的一种来源。
4. **尖灭：** 窄带在一端收窄到 0 时，线对候选应允许"一端开口"，不要求两条线在两端都闭合。这一点影响 C-PAIR 的设计。
5. **所有硬约束都必须有出处：** 每个 PROTECT 或 MERGE 决定都记录触发它的证据和所属独立组，写进 GIS 属性。

## 8. ≤ 6 px 专用候选生成器 C-PAIR（研究重点）

**目标：** 在 B2 线图上，找出两条线之间的窄带，作为候选窄单元。

**要区分的三类对象（按 D1 的统计）：**

| 对象 | 特征（假设，阶段一要用数据检验） | 规模（训练图，宽 < 6 px） |
|---|---|---|
| 真实细长地层 | 两条线之间的颜色与两侧不同；宽度通常明显大于印刷线宽；走向连续，可能尖灭 | 111 个 |
| 印刷接触线被切出的墨带 | 宽度接近印刷线宽；带内大部分是墨线；带内颜色与一侧邻居相同；两条"线"其实是同一条墨线的两侧 | 1,380 个伪碎片中的大部分 |
| 两条普通线之间偶然形成的窄带 | 两条线来源不同（例如接触线和等高线）；走向不一致或只在一小段内平行 | 待测 |

**设计要求：**
- **允许弯曲：** 按局部走向测量间距，不假设线是直的。
- **允许断续：** 两条线之间短于若干像素的缺口可以跨越。
- **允许尖灭：** 一端开口。
- **当前图幅的印刷线宽要从图像估计，而不是写死：** 两次线宽估计器都失败过（R4-B0、R4-B0.1），这里换个思路，按每条墨线的截面测宽，不按连通域测。
- **输出：** 候选掩膜、间距序列、证据统计，以及它属于上述三类中哪一类的分数，不直接下结论。

## 10. 分阶段路线（在您的四阶段基础上调整）

| 阶段 | 内容 | 使用的图 | 门槛（证伪条件） |
|---|---|---|---|
| **一：证据审计与 Oracle 上限** | (1) 每类证据在各尺度区分"真实单元 / 伪碎片 / 墨带"的能力（AUC、在固定召回下的误报率）；(2) "完美证据"消融：用官方标签替代某一类证据，看 RAG 召回上限提高多少；(3) 分级公共细分的规模；(4) 墨带截面线宽估计的验证；(5) 封存测试池的规则（不下载） | 训练图 + 已暴露图 | 某类证据的完美版本让上限提高不到 0.01，就不开发这类证据 |
| **二：多尺度候选生成** | C-PAIR 第一版；线图；分级公共细分 | 训练图 + 已暴露图 | 3–6 px 的 Oracle A 上限从 0.45 提高到至少 0.65，且区域数不超过只用 B2 时的 3 倍；做不到就不进入阶段三 |
| **三：统一区域图中的多证据融合** | 决策状态、冲突规则、伪碎片吸收（方案 A 作为其中一个 MERGE 规则）、拓扑约束 | 训练图选参数；已暴露图看方向；**测试池前 3 幅只评价一次** | 预注册：小实例召回不低于 RAG_BOUNDARY_ONLY；伪碎片减少 ≥ 40%；3–6 px 和 6–10 px 不下降超过 0.03；过分割不超过 M2_hybrid + 0.03 |
| **四：按失败证据决定是否训练** | 只有阶段三的失败分解指向"证据本身不够"时，才考虑新训练（区域关系模型、线分类、图例条件化）或扩大 GSJ 数据 | — | 由阶段三的失败分解决定 |

**为什么这样排序：** 阶段一用 Oracle 消融决定哪些证据值得开发，避免一次开发十几个模块；阶段二先补上"窄候选在融合前就丢失"这一不可恢复的缺陷，因为阶段三的融合规则再好也救不回已丢失的候选；阶段三才处理冲突和清理。

**测试池：** 协议已写在 `experiments/ARCH0/test_pool_protocol.json`，只有规则和候选顺序（从 validation_order 第 14 位开始：15042、15096、15059、13087、13012、14086……），没有下载任何图。08011、08021 不纳入。规则：
- 每幅图最多用于一次决策；
- 一旦用其结果修改方案，该图永久降级为已暴露图；
- 建议 3 幅用于阶段三门槛，3 幅留给最终冻结评价。

## 11. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 训练图太少，多证据、多阈值容易过拟合 | 阶段三在新图上失效 | 每类证据最多 1–2 个参数；只在训练图上定参数；在已暴露图上检查方向是否一致 |
| G-NET 内部高度相关被误当作多项证据 | 错误合并或错误保护 | 按独立组计数（§4） |
| 窄层与墨带外观重叠，数量相差约 10 倍 | 保护窄层的同时保留大量伪碎片，或清理伪碎片时误删窄层 | 用 UNCERTAIN 吸收冲突；阶段一先测可分程度 |
| 测试图消耗过快 | 失去独立评价能力 | 测试池协议；阶段内只用训练图和已暴露图 |
| 线宽估计第三次失败 | C-PAIR 无法区分墨带 | 截面测宽方法先在合成图和训练图上验证；失败则 C-PAIR 只用颜色区分 |
| 在中国图上，B2 的边证据本身不可靠 | 整个架构在中国图上的上限受限 | 准备少量中国图人工真值；加大颜色证据（不依赖色表）的比重 |
| 复杂度增加而收益很小 | 投入浪费 | 每增加一个模块都做消融：没有独立增益就不保留 |
