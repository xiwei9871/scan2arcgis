# R2 评价诊断：配准独立性、指标拆分、图例审计、Oracle（2026-10-28）

本轮只新增评价、诊断和数据核验代码。R1 识别算法、`gsj_run_r1.evaluate()` 均未修改。
开发图：08004 榛名山、08001 坂城。验收图 08011 那珂湊、08021 石岡已封存（见第 6 节）。
结果 JSON：`experiments/R2_real_map/results/diagnostics/`。

## 1. 配准独立验证

**方法（`gsj_reg_independent.py`）：** 用 black-hat 形态学响应提取细黑线。它只对墨线有响应，对两种平涂色之间的颜色台阶几乎没有响应。
在每个官方接触线像素周围取 41×41 窗口，把上万个窗口叠加平均。等高线、文字等无关线条会平均成背景，真正印刷的界线会在真实偏移处形成峰值。
峰值位置就是配准残差，峰值对比度 z 表示信号是否可信。这个检验只用 `geo_L` 几何和单应矩阵，不用填色，也不用单元标签。

**废弃的检验：** 逐像素“到最近墨线的距离”（`gsj_reg_check.py`）没有区分力。08004 上墨线只占图面 0.95%，只用图廓配准时中位距离 19.0 px，随机平移 15–40 px 的基线是 18.1 px，两者几乎一样。这个结果只记录，不采用。

| 图幅 | 配准 | 全局残差 dx, dy（200 dpi px） | 峰值 z（平移 30 px 的对照） | 可信格子 | 格子残差 中位 / 最大 |
|---|---|---|---|---|---|
| 08004 | 只用图廓 | 4.2, 1.7 | 2.7（4.3） | 9 / 16 | 24.6 / 28.3 |
| 08004 | **颜色细化（现用）** | **−0.1, 0.9** | **10.8**（4.0） | 16 / 16 | **1.1 / 6.7** |
| 08004 | 墨线细化 | −1.9, −1.9 | 11.5 | 16 / 16 | 2.3 / 9.4 |
| 08001 | 只用图廓 | 20.0, 2.9 | 3.1（5.1） | 7 / 16 | 20.4 / — |
| 08001 | **颜色细化（现用）** | **0.9, 0.5** | **15.1**（5.1） | 16 / 16 | **1.0 / 2.6** |
| 08001 | 墨线细化 | 0.5, −0.3 | 10.4 | 16 / 16 | 1.8 / 15.4 |

**结论：**

- 独立的墨线证据显示，现用的颜色细化配准全局残差小于 1 px，格子残差中位约 1 px，最大 6.7 px（08004）和 2.6 px（08001）。
- 直接用墨线做细化并没有更好。所以颜色细化没有把真值“拉向”颜色分类器，至少在 200 dpi 下 1–2 px 的精度内没有。
- **图廓不能作为独立控制点。** 两幅图都是双线图廓：图廓检测锁定外框，细化后的图幅四角在内侧约 90 px 处，而沿图廓的线响应峰值在 ±60 px 范围内不一致。四角刻度控制点没有实现。

## 2. 配准扰动敏感性（`gsj_sensitivity.py`）

R1 预测固定不变，只扰动真值的配准。表中位移是 200 dpi 像素，评价尺度为 100 dpi，线容差 1.5 px。

| 扰动 | 08004 mIoU | 08004 接触线 F1 | 08001 mIoU | 08001 接触线 F1 |
|---|---|---|---|---|
| 无 | 0.452 | 0.478 | 0.359 | 0.441 |
| 对角平移 2 px | 0.450 | 0.493 | 0.359 | 0.464 |
| 对角平移 4 px | 0.444 | 0.476 | 0.354 | 0.443 |
| 对角平移 8 px | 0.425 | 0.395 | 0.331 | 0.336 |
| 对角平移 16 px | 0.384 | 0.274 | 0.292 | 0.238 |
| 缩放 0.2% | 0.445 | 0.464 | 0.351 | 0.394 |
| 旋转 0.1° | 0.448 | 0.446 | 0.357 | 0.420 |

- 在已验证的残差量级内（≤2–4 px），mIoU 变化不超过 0.008，接触线 F1 变化不超过 ±0.023。所以配准误差不是 mIoU 偏低的原因，但它对线指标有可见影响。
- 平移 2 px 时，接触线 F1 反而**上升**。说明印刷墨线和官方矢量之间有亚像素级的系统偏移，以后报告线指标时要带上这个不确定度。
- **排除边界带后的单元内部指标**（忽略官方边界 8 px 以内的像素）：08004 mIoU 0.521（覆盖 79% 像素），08001 mIoU 0.416（覆盖 70%）。也就是说，大部分错误发生在单元内部，不在边界带。
- 本表基准 0.452 与上一轮的 0.454 不同，是因为本表在工作尺度直接栅格化，上一轮是从 200 dpi 下采样。

- R1 唯一能给类别命名的手段，是对色块做 tesseract OCR。结果是乱码，例如 `pot`、`a`、`om`。所以**系统自主的语义准确率为 0**。
- 区域上限和语义之间的全部差距，都来自“不知道哪块是哪个地层”。

- 拓扑里的邻接指标借用了上限映射，同样属于上限。

## 4. 图例审计（xlsx 官方 RGB 和代号，对照检出的色块）

| 分类 | 08004（42 个图面单元） | 08001（45 个） |
|---|---|---|
| 检出（有色块与官方 RGB 的 ΔE<10） | 31（占面积 67.0%） | 37（97.6%） |
| 同色异类（与其他单元官方 RGB 的 ΔE<3） | **6（27.2%）** | 5（0.8%） |
| 没有独立色块（图例表无代号，如水域） | 2（0.8%） | 1（1.4%） |
| 漏检（颜色独立、有代号、但没有匹配的色块） | 3（5.0%） | 2（0.1%） |
| 分类粒度：图例有、图面没有 | 3 条（38、5、7） | 0 |
| 检出但对不上任何单元的色块 | S10、S12 | S01 |

- **08004 的同色异类：** {Mz, Sm, Jg, Hf} 四个单元，以及 {Ohf, Ic} 两个单元。其中 Ohf 是全图最大的单元，所以同色异类占到面积的 27%。只靠颜色，理论上无法区分这些单元。
- **08001 的同色异类：** {M3, Ob} 和 {t1, t2, t3}，面积很小。
- **“漏检”的边界情况：** 包括颜色超出阈值的情况。例如 08004 的冲积层 `a`，最近的色块 ΔE 是 12.9，占面积约 5%。它是真的漏检，还是图例印刷色和 xlsx 参考色有偏差，需要人工看一眼图例栏确认。
- 原来报告的“36/42 个色块”，主要不是漏检。42 个单元的构成是：31 个检出，6 个同色异类，2 个没有独立色块，3 个漏检；另外图例表有 45 条，其中 3 条在图面上没有出现。

## 5. Oracle 诊断（`gsj_oracle.py`，只用于评价）

所有方法都在同一批像素上评分：图内、官方单元内、非墨线。
- **理想区域：** 直接用官方多边形的连通块作为区域，但隐去单元身份。
- **direct：** 方法直接输出官方单元，这个分数就是语义准确率。
- **上限：** 方法输出的是色块类别，评分用匈牙利映射，结果是上限。

| 方法 | 08004 准确率 / mIoU / IoU≥0.5 | 08001 准确率 / mIoU / IoU≥0.5 | 评分 |
|---|---|---|---|
| R1 rf_selftrain | 0.829 / 0.468 / 20 | 0.735 / 0.383 / 17 | 上限 |
| 逐像素 × 检出色块颜色 | 0.790 / 0.399 / 18 | 0.707 / 0.335 / 14 | 上限 |
| 逐像素 × xlsx 官方 RGB | 0.590 / 0.391 / 16 | 0.654 / 0.314 / 12 | direct |
| **逐像素 × 理想颜色**（图内各单元的颜色中位数） | 0.815 / **0.554** / 25 | 0.770 / **0.531** / 27 | direct |
| **理想区域** × R1 像素投票 | **0.918 / 0.596** / 27 | **0.828 / 0.478** / 21 | 上限 |
| 理想区域 × 检出色块颜色 | 0.902 / 0.556 / 25 | 0.851 / 0.483 / 23 | 上限 |
| 理想区域 × xlsx 官方 RGB | 0.627 / 0.453 / 19 | 0.666 / 0.408 / 19 | direct |
| 理想区域 × 理想颜色（留一区域） | 0.506 / 0.360 / 15 | 0.807 / 0.490 / 20 | direct |

解读：

1. **完美分割的增益有限。** 理想区域配上 R1 投票，mIoU 只提高 0.10–0.13，达到 0.60 和 0.48。即使边界全对，按上限映射也还有 40–50% 的 mIoU 损失，这部分来自区域被归到了错误的单元。
2. **完美颜色的增益也有限。** 逐像素用理想颜色，mIoU 0.55 和 0.53。说明光靠颜色，即使颜色估计完美，近色和同色单元也区分不开。
3. **两者叠加仍然不够。** 理想区域加理想颜色（留一区域）在 08004 上只有 0.36。原因是 08004 很多单元只有一块区域，留一法下无法预测。08001 上是 0.49。
4. **xlsx 官方 RGB 不能代替图例色块。** 逐像素准确率 0.59，低于检出色块的 0.79。出版方的参考 RGB 和实际印刷色有偏差，而且 GSJ 说明里也写了花纹没有编码进 RGB。

## 7. 判断：下一步优先突破哪一个

**优先突破图例语义关联，区域级分类作为它的载体同步做。不把边界分割作为主攻方向。**

依据：

1. **语义关联是硬瓶颈。** 系统自主的语义准确率是 0，而区域上限是 0.70–0.82。不解决语义关联，任何分割改进都无法变成可用的地层属性。
2. **分割改进的天花板有限。** 完美分割只带来 +0.10–0.13 mIoU。配准误差在已验证范围内对 mIoU 的影响不超过 0.008，单元内部的错误占多数。
3. **单靠颜色无法完成命名。** 理想颜色只能到 0.53–0.55；同色异类在 08004 占面积 27%；xlsx 官方 RGB 比检出色块更差。命名必须引入颜色以外的证据。

下一轮实验需要人工批准，按约定本轮不开始。建议这样做：
- **语义：** 识别图面上的地层代号和图例框内的代号，用来建立“区域 → 官方代号”的对应。
- **分割：** 在区域级聚合颜色和纹理，作为命名的载体。
- **评价：** 主要指标改为“系统自主语义 mIoU”，区域上限作为对照。
