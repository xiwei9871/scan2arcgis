# ARCH-2 任务二：公共细分实现勘误（2026-10-30）

起点：`29c1a9c87202a64fff694c2f6e4d603eab53d07b`。ARCH-1 的 `experiments/ARCH1/arch1_gate4.py` 和结果保持不变，本文件是勘误。
新实现：`experiments/ARCH2/arch2_subdivision.py`；测试：`tests/arch2/test_arch2_subdivision.py`（6 项）；重新测量：`experiments/ARCH2/arch2_subdivision_recheck.py`，结果 `experiments/ARCH2/subdivision_recheck/recheck.json`。
重新测量仍然用官方窄实例做 Oracle 替身，**不是自主 C-PAIR 的结果**。

## 1. 缺陷确认

您指出的问题成立。ARCH-1 的 `graded()` 在计算分区键时，只要 `cand_lab > 0` 就使用候选标签，所以即使候选边界在"1 px 去重"后一个像素都没加，候选内部标签仍然会切开基础分区。合成测试复现了这一点：

| 情况 | 期望 | ARCH-1 `graded()` |
|---|---|---|
| 候选边界与已有边界完全重合 | 不增加区域 | 不增加（正确） |
| 候选边界偏移 1 px | 按去重规则不增加 | **增加了 1 个区域，同时报告"新增边界 0 px"**（错误） |
| 独立条带 | 增加 1 个区域 | 增加 1 个区域（正确） |

所以 ARCH-1 Gate 4 中的"1 px 去重"实际上没有起作用。那次测到的 1.6–2.2 倍，其实是"候选整体加入、不去重"时的区域规模。

## 2. 两种修正规则

**规则 1：像素对级去重**（`graded`）。如果某个候选像素对的 3×3 邻域里已有同方向的基础分隔，就丢弃这个像素对。最终的分隔严格等于"基础分隔 ∪ 保留的候选像素对"。单元测试保证：基础分隔全部保留，不会出现声明之外的切割。那些保留下来但没能闭合的像素对单独计数为 `dangling_kept_pairs`，不会被悄悄当成切割。

**规则 2：区域级去重**（`graded_region`）。如果某个基础区域已经覆盖候选的 ≥ 90%，且面积不超过候选的 1.5 倍（说明这个候选已经被分开了），就跳过它；否则把候选的完整边界加入。

## 3. 重新测量（10 幅训练图 + 13014、15076）

| 规则 | 区域数 / 只用 B2（中位 / 最大） | 3–6 px Oracle A（训练 / 暴露） | 6–10 px Oracle A（训练 / 暴露） |
|---|---|---|---|
| 只用 B2（基准） | 1.00 / 1.00 | 0.45 / 0.64 | 0.90 / 0.90 |
| 规则 1：像素对去重 | **1.00 / 1.00** | **0.48 / 0.65** | 0.90 / 0.90 |
| 规则 2：区域去重 | 1.60 / 2.20 | **1.00 / 1.00** | 1.00 / 1.00 |
| ARCH-1（有缺陷） | 1.60 / 2.21 | — | — |

**这是一个重要的新发现：像素对级去重会让窄候选失效。** 3–6 px 地层的边界本来就和 B2 的边界相距 1–2 px（B2 的边落在印刷线上，窄地层贴着印刷线），所以候选边界的大部分像素对被当作重复丢掉了。剩下的像素对无法闭合（例如 15076 上有 16,953 个这样的像素对），候选没能切出来，Oracle A 几乎没有提升。

**结论：**
- ARCH-2 采用**区域级去重**（规则 2），参数 cover = 0.9、size = 1.5，预先固定。
- ARCH-1 中"1.6–2.2 倍"这个数字**大致可以保留**，但它对应的是区域级加入，不是 ARCH-1 文中描述的像素对去重；而且这仍然是 Oracle 候选的规模，不能当作未来真实 C-PAIR 的工程保证。真实候选中会有大量误检，区域数必须在 ARCH-2 Gate 1 重新测量。
- 像素对级去重保留在代码中，只用作对照。

## 4. 测试覆盖

- 完全重合的候选：不增加区域；
- 偏移 1 px 的重复边界：像素对规则不增加区域，并报告丢弃数；
- 独立条带：逐像素保留；
- 随机分区：基础分隔全部保留，没有声明之外的切割，所有区域都是四连通的，未闭合的像素对如实报告；
- T 形交汇：候选在接触已有边界处保持闭合；
- 区域去重：已被分开的候选会被跳过，未被分开的候选被逐像素保留。
