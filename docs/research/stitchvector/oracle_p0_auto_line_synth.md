## 0. 结论

**P0：四个问题都已查明原因，其中 A、C、D 已修正；B 只修正了一部分。**

| 问题 | 原因 | 处理 | v2 结果（32 色，tol 0） |
|---|---|---|---|
| A 保护带在合成图中被覆盖 | v1 画线时没有排除保护区；23 px 来自 G2（20）和 LOOP（3） | 线和符号一律不画在保护像素上 | 保护像素与标签一致率 1.000（v1 为 0.958） |
| B 线条保真 | 见 1.2：G1 的 0.00 主要是采样问题；颜色取自浅色边缘；三角齿用中心线表达不合适 | 颜色改为沿线密采样的原图中值；三角齿改为小多边形 | 红线变好；三角齿**变差**；G1/G2 仍压在颜色分界上 |
| C 回读差异 | tol 0 的 9 px 来自 `width_px` 保存为两位小数（B、C、LOOP、F3），面层回读完全一致 | 宽度按全精度保存；所有指标改为从写出的 GPKG 重新绘制后计算 | 未覆盖像素 0；指标即文件质量 |
| D 白纸稀释 | 有效图面只有 x < 94 | 分别报告全窗口、图面、线邻域（离线 ≤ 3 px）、图面其余部分、保护带 | 见 1.1 |

**P1：自动描线在合成图上能找到大部分线的位置，但没有一条线是"连续的"，淡色线基本失败，窄色带保护不稳定。**

- 去掉颜色类之后，D71 的第一个失败点已解决：同一条红线的不同深浅不再被拆散。D71 分类器在相同合成图上的召回率平均为 0–0.10，新检测器为 0.62–0.93（淡色线除外）。
- 按预注册标准（召回 ≥ 0.9 且最多 2 个对象），40 条测试线中**0 条连续**，13 条"找到但破碎"，27 条"漏检"。破碎主要发生在交叉处，每条线平均被拆成 2.4–7 个对象。
- 淡色细线 pale_1 召回 0.23，5 个测试图全部漏检。
- 从红色填色面内出发的红线（red_touch_fill）召回 0.66，D71 的第二个失败点只缓解了一部分。
- 窄色带：10 条中 7 条通过（轴线上有线的比例 ≤ 0.1）。失败的 3 条宽 3–4 px，其中最差一条有 52% 的轴线被误画了线。原因是色带边缘的抗锯齿混合色没有被识别为填色混合。
- 误检长度占 7.3%，主要是填色面的边缘被当成了线。
- 开发种子的结果比测试种子好（开发种子窄色带最差 0.06，测试种子 0.52），说明检测器在开发种子上已经偏乐观。

**下一步建议（第 4 节）：** 继续自动描线，但先只解决三件事：交叉处的连接、填色边缘与线的区分、窄色带边缘的混合色。在这三件事于合成图上通过之前，不进入真实样区。

### 1.3 v2 修正效果

- 红线：颜色改为沿线密采样中值后，存在率 A 0.96、C 0.95、LOOP 0.84、F3 0.77、F2 0.74（v2 新采样口径，B0 在同一口径下为 0.09、0.00、0.62、0.49、0.47）。
- 三角齿改为小多边形后**变差**：存在率 0.07–0.62，低于 B0。原因（`posthoc_symbols.json`）：符号多边形取线迹 2 px 内的全部墨迹，其中约一半是浅色晕边，多边形颜色取的是中值，比线迹颜色浅（R 通道多数浅 19–58，F2t1 只浅 6）。修正方向是用多边形内最深的一部分像素定颜色，或者把小三角当作"轮廓线 + 内部透明"的符号，本轮没有再改。
- 非简单几何：v2 中 0 个（F2t1 改为多边形后有效）。

## 2. P1：自动描线合成试验

### 2.1 设置

- 生成器 `sv_synth.py`：256×256，粉色底，绿/黄/红三块填色面；两条 3–6 px 的填色窄带（必须保护）；8 条线：红色抗锯齿 2 px、3 px（沿线颜色有 ±12% 深浅变化），黑色 1/3/5 px，淡色 1 px，红色 2→5 px 渐宽，以及一条从红色填色面内部出发的红线。4 倍尺寸绘制后缩小（抗锯齿），加高斯噪声 σ = 2，再做 JPEG 质量 75 压缩。真值是每条线的轴线和宽度。
- 检测器 `sv_autoline.py`，不用任何标签，也不按颜色类拆分：对比度（相对 15×15 中值背景的 dE）→ 从宽的低对比区域找出填色颜色 → 接近某种填色、或位于两种填色混合线段上的像素受保护 → 其余高对比像素为墨迹 → 骨架 → 去毛刺 → 交叉处按方向（≤ 35°）直通连接 → 平滑、1 px 简化。
- 开发种子 1001–1003 在冻结前运行过，结果随预注册提交（`autoline_dev.json`）；测试种子 2001–2005 在冻结后只运行一次，6.3 s。
- 对照：D71 冻结的 L/P/U 分类器，在同一合成图的 32 色量化上运行。

### 2.2 结果（测试种子，每类线 5 条）

| 线 | 召回均值 | 平均对象数 | ≥3 px 缺口 | 连续 / 破碎 / 漏检 | 宽度误差 px | D71 召回 |
|---|---|---|---|---|---|---|
| red_aa_2 | 0.87 | 7.0 | 3.0 | 0 / 2 / 3 | 0.28 | 0.03 |
| red_aa_3 | 0.82 | 6.6 | 3.4 | 0 / 2 / 3 | 0.00 | 0.00 |
| black_1 | 0.93 | 4.0 | 2.4 | 0 / 4 / 1 | 0.16 | 0.00 |
| black_3 | 0.91 | 6.2 | 2.4 | 0 / 3 / 2 | 0.16 | 0.00 |
| black_5 | 0.84 | 3.4 | 2.8 | 0 / 2 / 3 | 0.08 | 0.00 |
| pale_1 | 0.23 | 1.2 | 6.8 | 0 / 0 / 5 | 0.00 | 0.10 |
| red_var_2to5 | 0.62 | 3.6 | 3.4 | 0 / 0 / 5 | 0.42 | 0.07 |
| red_touch_fill | 0.66 | 2.4 | 2.0 | 0 / 0 / 5 | 0.20 | 0.00 |

判定标准（预注册）：连续 = 召回 ≥ 0.9 且覆盖对象 ≤ 2；破碎 = 召回 ≥ 0.9 但对象更多；漏检 = 召回 < 0.9。

窄色带：10 条中 7 条轴线上有线的比例 ≤ 0.1。失败的三条：2001 黄色 3 px（0.52）、2002 绿色 4 px（0.33）、2004 黄色 3 px（0.12）。
误检长度：平均 7.3%。

### 2.3 失败原因（运行后看图和描述性统计，`posthoc_test.json`，不是预注册指标）

1. **交叉处断开。** 叠加图上断开大多出现在交叉点。直通连接只在两段骨架共用同一个节点时生效；抗锯齿交叉在骨架上通常变成两个节点加一小段短链，连接规则跨不过去（推测，未逐个核实）。这是"找到但破碎"的主要原因。
2. **渐宽线部分丢失。** red_var_2to5 按长度三等分的召回：2002–2004 中段只有 0.28–0.50；2001 则是两端丢失（0.08、0.05）。宽度误差只有 0.42 px，所以不像是宽度本身的问题；具体原因没有逐条核实，我推测与交叉和填色面接触有关。
3. **填色面边缘被当成线。** 叠加图上可以看到红、黄、绿填色块的轮廓被描成线，这是 7.3% 误检的主要来源。填色面的抗锯齿边缘对比度高、宽度窄，现有判据区分不了。
4. **窄色带边缘没有被识别为混合色。** 3–4 px 的色带几乎全是抗锯齿像素，颜色既不接近色带颜色、也不在两种填色的混合线段上（背景粉色、色带色和 JPEG 噪声三者混合），于是成为墨迹。
5. **淡色线对比度太低。** pale_1 与粉色背景差约 10–15 dE，接近墨迹阈值 12 和 JPEG 噪声。
6. **从红色填色面内出发的红线**召回 0.66。推测原因是填色面内这一段与周围红色的对比度低于墨迹阈值，未逐段核实。

### 2.4 与 D71 相比

D71 分类器在这些合成图上几乎找不到线（召回 0–0.10），因为它先按颜色类划分候选。新检测器不按颜色划分，红线和黑线召回 0.82–0.93。所以 D71 的第一个失败点（颜色深浅把线拆碎）确实解决了；第二个失败点（线与同色填色相接）只解决了一部分。

## 4. 独立判断与下一步

**问题：** 在有真值的合成图上，能否低成本自动生成连续、准确、可编辑的线，同时保护真正的窄色带？

**回答：** 现在还不能。位置大体能找到（红线、黑线召回 0.82–0.93，宽度误差 ≤ 0.42 px，耗时每图 < 0.1 s），但连续性、淡色线和窄色带保护都没有达标：
- 连续性是最大的问题：0/40 条连续，交叉处断开。线面分层的编辑收益（一条线一个对象）依赖连续性，所以这一项不解决，自动描线就拿不到 Oracle 显示的收益。
- 窄色带 7/10 受保护，失败的都是 3–4 px 的窄带。这恰好是最需要保护的宽度。
- 开发种子上的结果比测试种子好，说明在 3 个开发图上看起来"可以"的规则泛化不足。

**建议的下一轮（需要新的预注册，仍只用合成图）：**
1. 交叉处连接：在骨架交叉的小邻域内按方向配对，跨过短链连接，而不是只在共用节点处连接。
2. 填色边缘与线的区分：线两侧都是同一种背景颜色或同一对填色；填色面边缘一侧是填色、另一侧是背景，且没有墨色核心。用沿法线的双侧采样判断。
3. 窄色带边缘：把"背景色—色带色"之间的混合色也纳入保护，而不只是两种填色之间。
4. 淡色线单独评价，不与红黑线的标准混在一起。
5. 每一步只在开发种子上调整，冻结后换一组新的测试种子（例如 3001–3005），2001–2005 不再用于调参。

Oracle 部分的线条保真问题（三角齿符号颜色、压在颜色分界上的淡色线）可以并入同一轮，但它们属于"线怎么画"，与"线怎么找"分开评价。
