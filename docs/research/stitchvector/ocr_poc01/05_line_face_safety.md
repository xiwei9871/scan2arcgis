# 05 地质线面安全审计（T4）

代码 `experiments/STITCHVECTOR/ocr_poc01/safety_audit.py`；结果 `results/safety_audit.csv`（每个 OCR 框一行）、`results/safety_summary.json`。

## 1. 隔离方式

- B2c GPKG 以 sqlite `mode=ro` 只读打开；审计前后 SHA-256 均为 `988df621…6fd7`，**未改动**。
- 文字清除只在内存中模拟，没有写任何文件。
- 模拟策略（运行前固定）：线完全在框内（1 px 容差）→ 允许自动隔离；线穿过框边 → `PENDING_HUMAN`，不切；框跨两个以上大面（≥ 200 px²）的颜色类 → `PENDING_HUMAN`。
- "真实地质线"只在 Oracle 窗口内有定义：B2c 线有 ≥ 50% 长度落在 Oracle 线 2.5 px 内。窗口占地图 4.5%，共 13 条这样的线。窗口外全部 NOT_EVALUATED。

## 2. 结果（各引擎端到端 1×+2× 框）

| 指标 | RapidOCR | PaddleOCR | Surya |
|---|---|---|---|
| 文字框数 | 127 | 143 | 124 |
| 未匹配任何真值的框（误检或真值漏标） | 13 | 24 | 20 |
| 命中非文字负样本的框 | 0 | 0 | 2 |
| 被地质线穿过的框 | 59 | 66 | 54 |
| 跨 ≥2 个底面颜色类的框 | 50 | 54 | 50 |
| 需人工判断的框（`PENDING_HUMAN`） | 72 | 81 | 71 |
| 会被自动隔离的线（不重复） | 190 | 200 | 237 |
| 其中 Oracle 确认的真实地质线 | **0** | **0** | **0** |
| Oracle 真实地质线穿过文字框（已转 `PENDING_HUMAN`，未切） | 1 | 1 | 2 |
| 未匹配真值、但会隔离线的框 | 8 | 19 | 16 |

## 3. 解读

- 在有真值的 4.5% 窗口内，三个引擎的框按上述策略都不会自动删除真实地质线；穿过文字的真实线都被转为人工判断。这是 13 条线的小样本结论，不代表全图无损。
- 窗口外：约一半的文字框被地质线穿过、或跨不同底面，必须人工确认。自动隔离的 190–237 条线大多是文字笔画被 B2c 识别成的短线，但没有真值证明，NOT_EVALUATED。
- 风险最大的是"未匹配真值、但会隔离线"的框：PaddleOCR 19 个、Surya 16 个、RapidOCR 8 个。这些框可能是符号、地质线或真值漏标的文字。自动清除前必须先人工确认它们是文字。
- 误检测风险：RapidOCR 框最少、最保守；PaddleOCR 召回高但多出约 10 个无真值框；Surya 有 2 个框落在负样本（地质线/符号）上。

## 4. 其他安全指标

| 指标 | 状态 |
|---|---|
| 真值范围内误清除的地质线数量 | 0（三个引擎，Oracle 窗口内 13 条线） |
| 面边界受影响区域 | 每个框跨越的面数和颜色类数见 `safety_audit.csv`（`faces_crossing`、`ground_classes_crossing`）；对错 NOT_EVALUATED |
| 被错误归属的碎面数量 | NOT_EVALUATED：没有地质单元真值 |
| 未确认对象数量 | `PENDING_HUMAN` 框 71–81 个 |

**结论：任何引擎都不允许自动清除文字底下的几何。** 清除必须经过人工复核关口，穿过框边的线一律不切。
