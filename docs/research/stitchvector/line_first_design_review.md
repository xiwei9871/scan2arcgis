## 0. 结论先行

1. **"先抽线、再成面、语义最后"在原理上成立，也有成熟基础。** 地图处理领域的文字/图形分离、颜色分层、ArcScan 式的中心线矢量化、图像修复（inpainting）都是现成方法。它不是新理论，这反而是好事：大部分组件可以复用。
2. **但 POC-01 的数据说明，GSJ 13014 上对象数膨胀的主因不是"线把面切碎"，而是颜色噪声。** VTracer default → spline，对象数增加 31.8 倍（17,333 → 551,815），顶点只增加 1.47 倍（2.03M → 2.98M）。多出来的约 53 万个对象，平均每个只带约 1.8 个新增顶点，也就是说它们几乎都是 1–3 px 的噪声斑块。线面分层不能直接消除它们。要让对象数下降，同时还要在"相对原图"的指标上保真，必须先回答：JPEG 噪声算不算需要复刻的信息。我的意见是不算（第 5 节）。
3. **每图自校准阈值 T 有两次失败的先例，不能当作已知可行。** R4-B0 Gate 4 的骨架宽度估计器在 10 张 GSJ 训练图上都给出中位宽度 1.0 px，缩放验证失败（0.5 倍时相对误差 1.0）；R4-B0.1 的墨量估计器结论为 `SCALE_ESTIMATOR_FAILED`。原因是 1–2 px 的线宽已经低于距离变换能分辨的最小单位。所以我建议改问题：**不去精确测"典型线宽"，而是测"哪个尺度以下的结构会被面域方法吃掉"**，用形态学粒度谱（granulometry）按颜色分别得出 T（第 2 节）。
4. **线面关系需要"两侧检验"，不能统一"先线后面"。** 一条窄结构两侧颜色相同时，它是压在一个面上的叠加物（等高线、文字），面应当在它下面连续；两侧颜色不同时，它要么是两个面的公共边界线，要么本身就是一个窄面（彩色地层带）。窄彩色带应进入面层，而不是线层（第 3、4 节）。这一点与讨论稿的 Layer 1 不同。
5. **建议架构是"抽取顺序先线，渲染顺序面在下、线在上"。** 这与上一份 `route_review.md` 的"先色块分区、后墨线叠加"并不矛盾：那份说的是图层顺序，这份说的是处理顺序。线先被识别并从面的输入中移走，面再由颜色形成无缝分区，线不负责闭合面。这样开放、断裂、交叉的线都不会影响面域。
6. **是否值得做成新主线：值得做一次带停止规则的最小 POC，还不值得直接定为主线。** 第一步不需要写算法：先对已有的量化标签图做"面碎片来源分解"，算出线面分层最多能省多少对象（第 7 节）。如果上限本身就很小，这条路就不必再走。

## 2. 每图自校准阈值 T

### 2.1 为什么不能直接测"典型线宽"

- 离散像素上，距离变换得到的宽度是量化的。项目里已经单元测试过：k px 宽的轴向条带，按现有公式偶数宽读成 k−1（`experiments/R4B1T/r4b1t_width.py`）。1 px 和 2 px 的线几乎无法区分。
- GSJ 10 张图的骨架宽度中位数都是 1.0 px，缩放到 0.5 倍后仍读 1.0，说明估计器已经顶在下限上（`gate4_transfer.json`）。
- 墨量估计器在 15023 上接受的连通线段只有 1–9 个，样本不足，方向偏差和缩放误差都没过（`c1_validation.json`）。

结论：T 不能依赖一个"线宽估计值"再乘以系数。

### 2.2 推荐做法：按颜色的粒度谱

T 的用途是保护：凡是会被"面域方法"吞掉的结构都要先保护。所以直接测量这个"吞掉"的尺度：

1. **噪声标定。** 在大面积平坦区域（局部方差最低的 5–10% 窗口）估计每通道噪声 σ（中位绝对偏差 MAD）。σ 同时给出 JPEG 噪声强度和后面判"颜色是否真的不同"的阈值，例如 ΔE > 3σ_ΔE。
2. **颜色簇。** 在噪声标定后做量化（中位切分或 k-means，簇数由"簇间 ΔE > 3σ"确定，不固定 32）。
3. **粒度谱。** 对每个颜色簇的二值掩膜，计算半径 r = 1, 2, 3, … 的形态学开运算移除的像素比例 PS(r)。细线和笔画集中在小 r 处出现峰值，大面在大 r 处才被移除。每个颜色得到自己的 T_c = 粒度谱累计达到该颜色"细结构质量"多数时的 r（具体分位数需要在合成数据上确定，不预设）。
4. **一致性检查。** 把原图缩放 0.5、0.75、1.5 倍重复上述步骤，T_c 应按比例变化（允许 ±1 px）。不满足就报告 `T_UNCALIBRATED`，退回保守值（比如对所有颜色取最大的 T），不悄悄采用。

粒度谱（Matheron/Serra 形态学）用 `skimage.morphology` 或 `cv2.morphologyEx` 即可实现，本机都有。

### 2.3 对讨论稿六个问题的回答

| 问题 | 回答 |
|---|---|
| 只用距离变换、骨架、连通性、颜色、形状统计能否定 T | 能作为辅助特征；单独用于定宽度已经失败两次。主判据用粒度谱，距离变换只用于逐分支的宽度属性 |
| 全图一个 T，还是分颜色/分区域 | 分颜色。黑色墨线、红色断层符号、窄彩色带的尺度不同。分区域只在缩放检查发现图幅内扫描不均时才加 |
| 能否用 1/2/3/5 px 小范围试跑来选 | 可以，作为第二判据：在一个小窗口分别用各个 T 运行整个流程，选"细结构召回率达标前提下对象数最少"的 T。这正是 H-M 方法论的用法 |
| JPEG 噪声误判为大量 1 px 线 | 三道筛：对比度（与局部背景 ΔE > 3σ）、长度（骨架长度 ≥ 若干倍宽度）、方向一致性（结构张量相干度）。孤立斑块三条都不满足 |
| 窄彩色带 | 不按"暗"挑。按"两侧检验"（第 3 节）分类，窄彩色带进面层，作为窄面保留 |
| 线局部从 2 px 增宽到 5 px | 不逐像素按 T 切。在骨架图上按分支判定：分支上多数位置 ≤ T 就整条保留为线，宽度存成沿线变化的属性；用滞后阈值（高低两个阈值）防止在粗段处断开 |

我对讨论稿倾向（"推荐阈值 + 局部自适应"）的意见：同意给推荐阈值；局部自适应应该放在**分支级**，而不是像素级。像素级自适应等于没有阈值，结果难以复现。

## 3. 线与非线：无语义的分类

不用语义，只用几何和颜色，可以把小尺度结构分成五类。判据都在骨架分支或连通块上计算：

| 类别 | 判据 | 去向 |
|---|---|---|
| 噪声 | 面积小、对比度 < 3σ、无方向一致性 | 并入周围面，不单独成对象 |
| 抗锯齿晕边 | 位于墨线与填色之间 1 px 内，颜色近似两者的线性混合 | 归入线（线宽属性吸收它），**不得单独成面** |
| 叠加线 / 符号 | 长、窄、两侧颜色相同（ΔE < 3σ） | 线层；面在下面连续 |
| 边界线 | 长、窄、两侧颜色不同、本身颜色是墨色（远离所有大面颜色） | 线层 + 在线中心位置形成两面的公共边界 |
| 窄面 | 窄、两侧可能不同、本身颜色与图上某个大面颜色接近，或内部颜色均匀且有两条平行边缘 | 面层，作为窄多边形 |
| 文字/小符号 | 一群短分支、高端点密度、紧凑包围盒 | 线层的"字形组"，用轮廓多边形（Potrace 式）而不是中心线 |

两侧检验做法：沿骨架每隔若干像素取法线方向两侧、距离 (宽度/2 + 2) px 处的颜色，统计相同的比例。

**会失败的场景：**
- 等高线正好压在两个颜色区的分界处：两侧不同，它会被当成边界线。几何上这是对的（那里确实有边界），但语义上它是等高线。这属于语义层的问题，不影响 F0/F1。
- 两种颜色接近的地层（ΔE 接近 3σ）：两侧检验会摇摆。要报告"不确定分支"的数量，不要强行决定。
- 斜线花纹（hatching）填充：大量短平行线，两侧同色，会被判成成百上千条叠加线。它实际上是一个面的填充样式。这一类确定性方法很难处理，是 AI 或"纹理面"规则的候选。
- 文字压在边界上：字形组下面的两个面边界被遮住，只能推断。

## 4. 细结构矢量化：中心线还是轮廓

建议**以中心线为主、轮廓为兜底**，按分支逐条决定：

1. 骨架（`skimage.morphology.skeletonize` 或 `medial_axis`，后者同时给出宽度）→ 去毛刺 → 构成图：节点为端点和交叉点，弧为节点之间的链。
2. 每条弧用 Douglas–Peucker 或 Visvalingam 简化（容差按 H-M 分档：先 1 px，确认可行再试 0.5 px），存为 LineString，属性：颜色、平均宽度、宽度变化系数。
3. **回读检验**：按宽度属性把线渲染回去（圆头端点），与原图在该弧邻域比较。不达标的弧（比如宽度变化系数大、或渲染与原图 IoU 低）改为轮廓多边形（Potrace/VTracer 描摹该弧的掩膜）。
4. **逻辑对象**：在交叉点按方向连续性（"良好延续"，两段夹角接近 180°）把弧串成一条长折线；颜色和宽度一致是必要条件。这样一条被三条线交叉的等高线是 1 个逻辑对象、4 段几何，而不是若干个面。

中心线的优点：一条 300 px 长的 3 px 线，一个对象、顶点数约为轮廓的一半（轮廓有左右两边），编辑时拖一条线即可。
中心线的风险：
- X 型交叉处骨架会变成两个 Y 节点加一小段，需要合并短弧（长度 < 宽度的弧）；
- 1 px 线的渲染宽度只能是整数像素，抗锯齿像素的颜色无法用"颜色 + 宽度"表达，F0 指标在线像素上会略低于逐像素描摹；
- 骨架在线端会缩短约半个宽度，端点需要延长。

|---|---|---|

## 5. 线稿约束下的面域恢复

### 5.1 基本做法：线不负责闭合面

1. 从标签图中移走"叠加线""边界线""字形组"像素，得到带孔的标签图。
2. **填孔（推断）**：孔中每个像素取最近的未遮挡像素的标签（`scipy.ndimage.distance_transform_edt(..., return_indices=True)`，即离散 Voronoi 分配）。叠加线两侧同色，填孔后面在线下连续；边界线两侧不同，填孔后两面在线的中心附近相接。
3. 对填孔后的标签图，用现有 `sv_arcs.py`（共享弧段网络 + `coverage_is_valid`）生成无缝分区。公共边界天然共享，不需要黑线闭合。
4. 颜色相邻但没有黑线的地方，边界就是标签变化处，与现在 R2 的做法相同。

这样处理时，开放线、断线、交叉线都不影响面域：面的形状只由颜色决定，线只是从输入中"挖掉再补上"的区域。这回答了讨论稿的"线可能不闭合"问题：不需要它们闭合。

### 5.2 来源标记（满足"推断不能当观测"）

- 每个面存两个面积：`observed_px`（在原图中可见的像素）和 `inferred_px`（填孔得到的像素）。
- 另存一张来源栅格：0 = 可见观测，1 = 线下推断，2 = 字形下推断，3 = 不确定。面的几何不分割，但任何质量指标都只在观测像素上计算。
- 线下推断的边界位置（两面在线下如何相接）在面属性中标记 `boundary_inferred_len`。

### 5.3 会失败的场景

| 场景 | 后果 | 判据 |
|---|---|---|
| 一条宽线（≥ T）下面实际有一个窄色带 | 色带在原图中不可见，填孔不会恢复它；这是信息上限，不是算法错误 | 报告，不修补 |
| 字形或符号覆盖了一个小面的大部分 | 小面被周围颜色吞掉 | 可见像素少于某个下限的面计数 |
| 大量斜线花纹 | 每条短线都被挖掉再填，面连续，结果正确；但线层多出成百上千条短线，对象数不降反升 | 短线数量 / 面积 |
| 颜色渐变（晕渲、阴影） | 量化把它切成条带，面碎片来自渐变，与线无关 | 颜色梯度平滑区域占比 |
| 标签量化把一个面中的 JPEG 噪声分成多色 | 碎片来自噪声，线面分层无效 | 见 5.4 |

### 5.4 遮挡以外的主要碎片来源：颜色噪声

这一点决定了线面分层的收益上限，需要单独说明。

POC-01 R1 数据（VTracer，raw RGB 输入，1000×1000 px 局部）：

| 样本 | default 对象 / 顶点 | spline 对象 / 顶点 | 对象倍数 | 顶点倍数 |
|---|---|---|---|---|
| 13014 | 17,333 / 2,027,185 | 551,815 / 2,979,507 | 31.8 | 1.47 |
| u2 | 3,256 / 350,214 | 78,412 / 496,082 | 24.1 | 1.42 |
| u3 | 2,384 / 232,586 | 28,619 / 333,850 | 12.0 | 1.44 |

对象数翻了十几到三十倍，顶点只多了不到一半。新增对象每个只贡献约 1.8–3.9 个新增顶点，是极小的斑块。spline 的高保真主要来自"把每一个噪声斑块都画出来"。

所以：
- 线面分层只能消除"线把同色面切开"造成的碎片；它对噪声斑块没有作用。
- 噪声斑块要靠**噪声标定后的颜色量化**来消除（2.2 第 1、2 步）。量化后的标签图上，一个面内的颜色变化被当作噪声丢弃，这必然降低"相对原图逐像素一致"的指标。这是有意的取舍，必须在评价中明确说出来，而不是事后发现。
- R1 中 quantized-32 + default 在 13014 上只有 14,085 个对象，但 dE90 为 21.4、细结构匹配 0.52，说明现有量化（全局中位切分 32 色）把细线颜色也量化掉了。细结构先抽出、再对剩余区域量化，正好可以针对这个缺陷：细线不参与面层量化，面层量化可以更粗而不伤细线。这是线面分层最有希望的收益点，但目前没有数据。

## 6. 保真评价与预期瓶颈

### 6.1 "97–98%" 必须先定义

现有数据先排除一种定义：**RGB 逐像素完全一致**。13014 上，即使 VTracer pixel 模式（565k 对象）相对原图的完全一致比例也只有 0.453，spline 为 0.409（`r1_summary.json` 的 `pareto_exact`）。JPEG 扫描图上逐像素一致 97% 只有 R0 式一像素一面才能做到，没有编辑价值。

建议的 F0 指标组（全部只在可见观测像素上计算，分区报告）：

| 指标 | 定义 | 建议目标（待预注册，非结果） |
|---|---|---|
| 噪声容限一致率 | ΔE76(原图, 重建) ≤ 3σ_noise 的像素比例，σ_noise 由 2.2 第 1 步得到 | 全图 ≥ 97% |
| 细结构召回 | 原图细结构候选像素（按第 3 节分类，不用标签）中，重建图在 1 px 内有同类颜色的比例 | ≥ 97%，单独报告，不并入全图 |
| 细结构连续性 | 原图细结构骨架的断点数 vs 重建图骨架断点数 | 重建图新增断点 ≤ 原图分支数的 2% |
| 边界位置 | 颜色边界的对称距离 95 分位 | ≤ 1 px |
| ΔE90 | 与 POC-01 可比 | 记录 |
| SSIM | 只作参考 | 记录，不作判据 |

细线面积小，全图一致率掩盖不了细线丢失的问题由第二、三项单独回答。第一项用噪声容限而不是固定 ΔE，使不同扫描质量的地图可比。

### 6.2 对象数与编辑成本

对象数不是编辑成本。建议同时报告：
- 面对象数、线对象数（逻辑对象，串联后）、几何段数、顶点数；
- 每百万像素的上述数量；
- **编辑代理指标**：修改一个逻辑图形平均要动多少个对象（例如一条等高线被拆成几段、一块地层被拆成几个面）。可以在合成图上精确计算，真实图上用颜色连续性近似。
- QGIS 实测（F2）：安装后再做，现在 `NOT_VERIFIED`。

### 6.3 预期瓶颈（按严重程度）

1. **噪声与量化取舍**（5.4）：决定对象数下限。线面分层不能解决它。
2. **细线颜色**：1–2 px 线几乎全是抗锯齿像素，没有"纯色核心"。用"颜色 + 宽度"重画后，线像素的 ΔE 必然高于逐像素描摹。噪声容限一致率在线像素上可能达不到 97%，这时应接受"细结构召回"作为线像素的主指标。
3. **交叉与端点**：骨架在交叉处和端点处的几何误差是中心线方法的固有问题，需要回读修正。
4. **文字和花纹**：对象数可能反升（5.3）。
5. **多颜色细结构相交**：红色断层穿过黑色等高线，交点颜色是混合色，两条线都要连续，需要明确"上下层"规则。

### 6.4 线面分层在什么地图上收益大

| 地图类型 | 预期收益 | 原因 |
|---|---|---|
| 大面积平涂 + 稀疏黑色线条（典型地质图主图区） | 大 | 面被线切开是主要碎片来源，且面颜色均匀 |
| 密集等高线 + 平涂 | 中到大 | 面连续收益大，但线对象多 |
| 密集文字、注记 | 小，可能为负 | 字形组对象多，面收益有限 |
| 窄彩色地层多（如 3–6 px 带） | 小 | 它们本来就是面，线面分层不改变它们；若误分进线层反而出错 |
| 晕渲、渐变、阴影 | 无 | 碎片来自颜色变化 |
| 低质量 JPEG 扫描（GSJ 13014 这类） | 取决于噪声标定 | 先解决噪声，才谈得上分层收益 |

## 7. 可证伪的最小验证

### 7.1 第 0 步：不写算法的上限分析（建议先做）

用已有的 u2 300×300 32 色标签图（R2 用过的同一张，8,252 个面），只做计数：
1. 用现有 `thin_mask`（EDT ≤ 1.5，已存在）标出细结构像素。
2. 把细结构像素按最近邻分给周围的非细结构标签（5.1 第 2 步，约 10 行 numpy）。
3. 数新的同色连通域数 N'。

`8,252 − N'` 就是"线把面切开"造成的碎片数的上限估计。
- 如果 N' 不到 8,252 的 70%（省 30% 以上），线面分层值得继续；
- 如果省得不到 10%，说明在这类样区碎片主要来自颜色噪声，应先研究噪声标定量化，线面分层延后。

这一步成本约半小时，只读已有标签图，不涉及阈值自校准，也不需要任何新工具。它可以在下一次授权实验中作为预注册的第一项。

### 7.2 合成图（用于自校准和分类，带真值）

自己生成 2 张 1000×1000 合成地图：已知的平涂面、1/2/3/5 px 黑线（含交叉、开放端、局部增宽 2→5 px）、3–6 px 彩色窄带、文字、斜线花纹；渲染时加抗锯齿，再分别做 JPEG 质量 75/90 压缩，并缩放到 0.5/1.5 倍。

真值完全已知，可以检验：
- T_c 是否随缩放按比例变化（±1 px）；
- 五类分类的混淆矩阵；
- 面层在线下是否连续（合成面的真实个数已知）；
- 来源标记是否正确（推断像素就是被线覆盖的像素）。

### 7.3 真实样区（无标签）

u2 300×300（与 R2 相同）和 13014 中心 1000×1000（与 R1 相同），只读图像像素；不访问封存测试池；13014 的官方标签不用于任何决策。

### 7.4 比较组（相同输入）

| 组 | 方法 |
|---|---|
| B1 | VTracer default（R1 已有） |
| B2 | VTracer spline（R1 已有） |
| B3 | 噪声标定量化 + `sv_arcs` 单次 tol 1（不分层） |
| L1 | 噪声标定量化 + 线面分层（线：中心线 tol 1；面：`sv_arcs` tol 1） |

L1 对 B3 的差别只有"是否分层"，这才是线面分层的纯效果。按 H-M，第一轮只做 tol 1（相当于"2 目"），不做 tol 0。

### 7.5 判定规则（草案，需在运行前推送并 `git ls-remote` 核验）

- **线面分层成立**：在合成图和至少一个真实样区上，L1 相对 B3，逻辑对象数减少 ≥ 30%，同时细结构召回不低于 B3，噪声容限一致率差距 ≤ 1 个百分点。
- **高保真低复杂度成立**：存在一组设置使 L1 在 13014 上同时满足：细结构召回 ≥ 0.97（与 B2 的 0.98 可比，注意定义不同时要换算）、对象数 ≤ B2 的 10%（≤ 55,000）。
- **自校准成立**：合成图上 T_c 缩放误差 ≤ 1 px，且真实样区上缩放一致性检查通过。
- **不成立时的处理**：任一条不满足，报告具体失败项，不在同一轮修补参数。第 0 步上限分析不足 10% 时，整轮 POC 只做合成图部分。
- **停止规则**：每个样区 CPU ≤ 10 分钟；超出即报告。

## 8. 确定性算法与 AI 的分工

| 步骤 | 确定性方法 | 是否需要 AI |
|---|---|---|
| 噪声标定、量化 | MAD、中位切分 / k-means | 否 |
| T_c 自校准 | 粒度谱 + 缩放一致性 | 否 |
| 细结构五类分类 | 几何 + 两侧检验 | 大部分否；斜线花纹、字形与线的歧义可能需要 |
| 中心线 / 轮廓矢量化 | 骨架、简化、Potrace/VTracer | 否 |
| 线下面域补全 | 最近邻填孔 | 否；只有被大面积遮挡（字形、图例框）时可考虑 |
| 无缝分区、拓扑 | `sv_arcs`、shapely coverage | 否 |
| 碎片合并成逻辑面 | 同色 + 只被细结构分隔 | 否 |
| 纹理/花纹面识别 | 难 | 是，候选 |
| 文字识别、图例匹配、地层赋值 | — | 是（OCR、M1/M2/B2/RAG） |

结论：可以把 AI 限制在纹理/花纹面、严重遮挡和语义层。AI 介入的位置应该记录为"推断"来源。

### 无语义 / 少语义 / 语义三种方案

| 方案 | 输入 | 能达到 | 风险 |
|---|---|---|---|
| 无语义（本文主线） | 只有像素 | F0、F1 | 对象数下限由噪声决定；花纹面处理差 |
| 少语义 | 像素 + 图例色卡颜色（只用颜色，不用名称） | F0、F1 质量更高：量化调色板直接来自图例，噪声问题大幅缓解 | 图例颜色与图面颜色有印刷偏差；需要先定位图例（项目已有图例相关工作） |
| 语义 | 像素 + 地层、断层类型 | F2 完整交付 | 依赖模型，错误会传到几何层 |

我的建议：少语义（图例色卡作为调色板）很可能是性价比最高的一步，因为它直接针对瓶颈 1。它不违反"不理解地质"的原则：只用颜色，不用名称。

## 9. 是否发展为 Scan2ArcGIS 新主线

**现在不建议定为主线，建议作为一条有停止规则的研究支线继续。**

理由：
- 支持继续的：原理上成立；面层已有严格拓扑的可用实现（`sv_arcs.py`）；大部分组件已在本机；POC-01 显示量化把细线颜色丢掉，而线面分层恰好针对这个缺陷。
- 让我保留的：对象数膨胀的主因在 13014 上是噪声而非切分；两次线宽估计失败说明自校准有实际难度；文字和花纹可能让对象数反升；QGIS 编辑体验完全没有验证。
- 决定点：第 7.1 节的上限分析。它在半小时内就能说明线面分层在真实样区上最多能省多少。如果上限小，就不必在这条线上投入算法开发。
