# StitchVector 技术路线评审：渐进式、无语义、高保真矢量复刻

状态：TECH_ROUTE_REVIEW（只做调研与设计，未运行实验、未安装新依赖、未改动任何 Scan2ArcGIS 代码或基线）
分支：`research/stitchvector`（从 `research/r4a-boundary-learning` @ `dee918d` 分出）

## 0. 先给结论

1. **"无语义复刻"成立，但对扫描图来说，严格无损（F0）和可编辑（F1）是两件不同的事。** 实测（第 2 节）：在 JPEG 扫描图上，同色 4 连通域几乎是一像素一个。F0 可以做，但它只是"把栅格存成多边形"，不具备编辑价值。真正要研究的是 F1：在可量化的误差预算内，用尽量少的几何对象重画原图。
2. **VTracer 适合作为 F1 的描摹引擎，SvgBot 只值得借鉴迭代框架。** VTracer 是 MIT 许可证，有 `cutout`（无缝镶嵌）模式和固定调色板；SvgBot 是 GPL-3.0、早期单人项目，它的残差过滤规则（去掉边缘带、丢弃小块）恰好会删除地图上的细线，必须重写。
3. **4→2→1 不应定义为降采样，而应定义为"残差容差与最小修补尺度"。** 原图始终保持全分辨率，三档只控制"哪些差异值得修补、用多粗的几何去修补"。
4. **图层顺序建议"先色块分区、后墨线叠加"。** 色块做成无缝分区（GIS 天然需要共享边界），墨线作为单独的叠加层。顺序相反会让色块被墨线切碎，这正是 RAG 伪碎片的来源。
5. **渐进式（R2）是否优于单次描摹（R1），现在没有依据下结论。** 必须在"相同最终保真度"下比较对象数和顶点数。如果 R2 不占优，就直接用 VTracer。
6. **本机目前缺少三样东西：VTracer、Potrace、QGIS（以及 GDAL 命令行工具）。** 只有 rasterio 1.4.4。POC 前需要您同意安装（第 9 节）。

## 2. 关键实测：扫描图上的"同色连通域"规模

1000×1000 px 局部（u2 为 780×1000），统计不同 RGB 值数与同色 4 连通域数：

| 样本 | 不同 RGB 值 | 同色 4 连通域 | 单像素连通域占比 | 每连通域平均像素 |
|---|---|---|---|---|
| u2（中国图 PNG） | 92,008 | 262,272 | 92.2% | 2.97 |
| u3（中国图 PNG） | 80,137 | 432,338 | 87.2% | 2.31 |
| 13014（GSJ GeoTIFF） | 350,726 | 997,183 | **99.8%** | **1.00** |

含义：
- 在 GSJ 扫描图上，**严格 L0 等于一像素一个多边形**。整幅约 1,000 万像素，就是约 1,000 万个面。这是数学上能做、工程上没有编辑价值的上限。
- 原因是 JPEG 压缩噪声和抗锯齿：肉眼同一种黄色，在数据里是几百种 RGB 值。**这部分"细节"不是地图信息，而是噪声**。
- 因此 F1 的第一步必然是颜色量化。"严格 RGB 一致"只适合作为 F0 的指标；F1 应当用"与原图的 ΔE 分布 + 细结构保留率"衡量，而不是逐像素一致率。

## 3. 三条路线

| | R0 严格无损 | R1 VTracer 单次 | R2 StitchVector 渐进 |
|---|---|---|---|
| 做法 | RGB 编码 → `rasterio.features.shapes` 同值 4 连通域 → GPKG | 固定调色板 + `cutout` + 某个 `simplify`，一次描完 | 粗描 → 残差 → 局部重描 → 接受/拒绝 → 更细一档 |
| 保真 | 100%（逐像素回读可验证） | 由调色板和容差决定 | 由停止准则决定 |
| 对象数 | ≈ 像素数（GSJ） | 待测 | 待测 |
| 依赖 | 已有 | 安装 vtracer | vtracer + 自写调度 |
| 作用 | 出处底稿、验证基准 | 成熟工具能做多好 | 渐进式是否值得自研 |

建议同时保留 R0 作为"出处层"：它不必给用户编辑，但让 F1 的每个对象都能追溯到原图像素（您提出的 R3 思路）。在 GSJ 上它的存储成本很高，可改为保存原 GeoTIFF + 量化色号栅格，按需生成。

## 4. 4→2→1 的数学定义

比较了三种定义：

| 定义 | 做法 | 问题 |
|---|---|---|
| 降采样尺度 | 先在 1/4 分辨率描，再放大 | 1–3 px 细线在 1/4 分辨率下直接消失，后续只能当"残差"补回，违背"不永久丢失细节" |
| 笔宽 | 线条强制 4/2/1 px | 改变原图线宽，不是复刻 |
| **残差容差 + 最小修补尺度（推荐）** | 全分辨率上计算残差；第 k 档只修补"宽度 ≥ s_k 且 ΔE ≥ t_k"的残差区域，描摹容差 `simplify = s_k/2` | 需要定义"残差区域宽度"，但这是纯几何量（距离变换），不涉及语义 |

推荐定义（第 k 档，s = 4, 2, 1）：
- 残差 `D = ΔE76(原图, 当前渲染)`；残差掩膜 `M_k = D ≥ t_k`（例如 t = 20, 12, 6）。
- 对 `M_k` 的每个连通块，用距离变换求最大内切宽度 w；只处理 `w ≥ s_k/2` 的块（1 px 档处理全部）。**不按面积丢弃，不剔除边缘带。**
- 用 VTracer 在原图该块范围内局部重描（`simplify = s_k/2`，`filter-speckle 0`），得到候选补丁。
- **接受准则（Primitive 式）：** 补丁使该块内 ΔE 平方和下降至少 x%，且新增顶点数 / 误差下降量 低于本档阈值；否则拒绝，该块留给下一档。
- 1 px 档之后仍不达标的像素，用 R0 的像素小面兜底（量化后同色合并），保证最终可以达到任意指定保真度。

"已正确的部分不重复处理"由掩膜自然保证：误差低于 t_k 的像素不进入 M_k。

## 5. 先描线还是先描色块

推荐 **先构建色块分区，再叠加线层**：

1. 颜色量化，得到每像素一个色号。
2. 把"深色细长"类（墨线、文字）单独提为线层：判据是颜色接近调色板中最暗的几种 **且** 局部宽度小（距离变换），纯几何。
3. 线层像素在色块层中用邻近色块颜色填补（最近邻或众数），然后对色块层做 `cutout`/多边形化，得到无缝分区，相邻面共享边界。
4. 线层单独矢量化：宽度稳定的用中心线 + 宽度属性；宽度变化大的用窄多边形；文字、花纹用 Potrace 墨迹多边形。
5. 渲染顺序：色块层在下，线层在上。回读比对用这个顺序。

理由：
- **遮挡：** 原图本来就是"色块上压墨线"，按这个顺序重建，误差最小。
- **共享边界：** GIS 需要的是色块之间的无缝分区。如果先描线、再让线把色块切开，色块会在每条等高线、每个字处断开，产生大量伪碎片（RAG 的伪碎片就是这样来的）。
- **非墨线的细色带**（例如 3–6 px 的彩色地层）属于色块层，不属于线层。只要不做面积清理，它就会作为一个窄面保留下来。复刻能否保住它，只取决于量化后它是否和两侧颜色分开，这一点需要在 POC 中测量。

## 6. 不用语义、不用神经网络如何保护细节

- **禁止三类常见清理：** 中值/开闭滤波、按面积丢小块、剔除边缘带。所有工具都要显式关闭（VTracer `--filter-speckle 0`）。
- **细结构专项指标**（第 8 节）单独统计，不让整体 SSIM 掩盖它们。
- **残差调度按宽度而不按面积排序**，1 px 档保证覆盖所有残差。
- **兜底：** 最后剩余的残差用像素小面补上，保证"该有的颜色在该在的位置"。

## 7. SVG → GeoPackage 会丢什么、怎么处理

| 信息 | SVG 中 | GPKG 中 | 处理 |
|---|---|---|---|
| 曲线 | 三次贝塞尔 | 只有折线（OGC Simple Features 无贝塞尔） | 按 0.25 px 弦高误差离散化；顶点数会增加，需计入复杂度指标 |
| 绘制顺序 | 文档顺序决定遮挡 | 无 | `z` 字段 + 分层（色块层 / 线层）；`cutout` 模式下色块无重叠，顺序不再重要 |
| 颜色 | `fill` 属性 | 无内置样式 | 存 `rgb` 字段，并生成 QML/SLD 样式按字段着色 |
| 孔洞 / 填充规则 | `evenodd` / `nonzero` | 多边形内环 | 用 shapely 按填充规则重建内环，并做有效性检查 |
| 变换矩阵 | `transform="matrix(...)"` | 无 | 解析后应用到坐标 |
| 描边线宽 | `stroke-width` | 无 | 线要素 + `width_px` 字段 |
| 拓扑 | 无 | 简单要素也不存共享边 | 色块分区直接从栅格多边形化得到（共享边逐像素一致）；需要真正拓扑时用 GRASS `v.clean` |
| 坐标 | SVG 像素坐标 | CRS | GeoTIFF：用其仿射变换和 CRS（沿用我们已有的半像素约定）；无配准 PNG：像素坐标、y 取负、不赋 CRS（与现有导出一致） |

因此更稳妥的路线是：**色块层直接从量化栅格多边形化写入 GPKG，不经过 SVG**；SVG 只用于 VTracer 局部补丁和线层，再解析转换。GPKG 优于 Shapefile（单文件、无 2 GB 和 DBF 限制、R-tree 索引），通过 pyogrio 直接写入，不模拟鼠标操作。

## 8. 最小 POC 计划（建议预注册）

**样本：** u2、u3、13014 各一个 1000×1000 局部（只读图像；13014 的官方标签只用于第 5 项离线诊断）。

**步骤：**
1. **R0：** RGB 编码多边形化 → GPKG → 回读，要求 100% 逐像素一致；记录对象数、文件大小、耗时、内存。
2. **调色板：** 在每个样本上用一种确定性方法（中位切分到 N 色，N = 8/16/32/64）生成调色板，R1 和 R2 共用。
3. **R1：** VTracer `cutout`，同一调色板，`simplify ∈ {0.5, 1, 2}`，`filter-speckle 0`，共 12 种设置/样本，得到"保真度—对象数—顶点数—文件大小"曲线。
4. **R2：** 第 4 节的 4→2→1 调度，同一调色板。
5. **细结构离线诊断（只 13014）：** 用官方标签统计 3–6 px、6–10 px 实例在 R1/R2 输出中，是否存在一个与其 IoU ≥ 0.5 的同色面。标签只用于评价。

**指标：** 量化后色号一致率、对原图 ΔE76 中位数和 95 分位、PSNR/SSIM、边界距离（色号边界的对称 Hausdorff 95 分位）、细线连续性（骨架断点数）、对象数、顶点数、SVG/GPKG 大小、耗时、峰值内存、QGIS 打开/缩放/保存耗时（如已安装）。

**关键比较：** 在 R1 曲线上插值到与 R2 **相同的 ΔE95 和细结构保留率**，比较顶点数和对象数。

**判定（草案，请审定）：**
- R0 回读必须 100% 一致，否则工具链有错，停止。
- **R2 值得自研**，当且仅当在三个样本中至少两个上，相同保真度下顶点数比 R1 少 ≥ 25%，且细结构保留率不低于 R1。否则采用 R1，StitchVector 只保留"兜底修补"一步。
- **F1 路线值得作为产品层**，当且仅当存在某种设置：ΔE95 ≤ 10、细结构保留率 ≥ R0 的 90%、每百万像素对象数 ≤ 2 万、GPKG ≤ 50 MB/百万像素、QGIS 可流畅缩放。

**成本：** 约半天，CPU 即可。

## 10. 自研与复用的边界

- **直接复用：** VTracer（描摹）、rasterio/GDAL（多边形化、回读）、shapely/pyogrio（几何与写入）、Potrace（墨迹对照）、GRASS `v.clean`（需要时做拓扑）。
- **值得自研的只有三块：** 宽度优先的残差调度与接受准则；"色块分区 + 线层"的分层与线下填补；面向地图的细结构保真评价。这三块是现有工具都没有、又直接决定地图复刻质量的部分。

## 11. 与原 Scan2ArcGIS 研究的关系

- 复刻不依赖 M1/M2/B2/RAG。
- F2（地质单元级结构化）以后如需要，可以在 F1 的色块分区上做分组，这正是 RAG 的工作，但输入会更干净（墨线已被分离为单独图层）。
- 已知的信息限制仍然存在：200 dpi 下，3–6 px 地层只有约 14% 的像素离墨线超过 1 px（R4-B1T）。复刻会忠实保留这些像素，但如果它们在原图中就是黑线中间零星的彩色点，复刻结果也是零星色点，而不会凭空变成一条完整色带。
