## 1. 口径

- 真值元素每 1 px 采样，输出几何（面边界、线中心线）每 0.5 px 采样。
- 真值样本"可复用"的条件：1.5 px 内有输出、方向差 ≤ 30°，并且处在连续 ≥ 5 个匹配样本的连续段内。
- 每个样本只归入一类，长度和面积从不相加：
  - **墨线**：线可复用 / 只有面轮廓（需要转换）/ 附近有几何但不可复用（需调整）/ 缺失（补画）
  - **填色边界**：面边可复用 / 只有线（需沿线切面）/ 需调整 / 缺失
  - **色带轴线**：两侧都有面边、且轴上有专属色带面（可复用）/ 有中心线（需加宽并转面）/ 色带面存在但不完整 / 需调整 / 缺失
- **G1a** 几何存在率 = 非"缺失"的比例；**G1b** 低成本可复用 = 可复用的比例；**G1c** 需转换 = 只有面轮廓、只有线、或只有中心线的比例。
- **G2**：补画长度（缺失）、调整长度、转换长度，单位都是真值轴线的像素数。
- **G3**：编辑操作按类型计数。补画和调整都按每段连续 ≥ 3 px 计一次。面的合并次数 = 每个真值区域分到的面数减 1，这是逐个操作的上界；GIS 的批量融合可能更少，**未验证**。

## 3. 解读

1. **补画已经不是主要工作量。** B2c 在三组数据上的墨线补画都很少。剩下的补画集中在淡橙色细线（u2）和少数色带。
2. **面层碎片是现在最大的人工成本。** 三种方案中，合并碎面和逐个改色的次数都在每张图约 200 次的量级，比补画多得多。线面分层（B0/B2c）把这一成本降低约三分之一，但没有解决。"按颜色批量改"只能少量减少这个数字（911 对 990），因为同一颜色常常同时出现在不同的真值区域里。
3. **窄色带存成线是可以接受的中间形式，但不是免费的。** 反例场景中 F0 把色带完整保留成面，B0/B2c 把 96% 变成了中心线，每条需要一次"加宽 + 线转面 + 扣除下层面"。PN2 说明这种修复可以很便宜，PN1 说明前提是中心线完整、而且逻辑组里没有混入其他线。
4. **面层的边界损失在三种方案中完全相同。** 色带的补画和调整量、反例场景中 25% 的填色边界缺失，都与选哪种线层无关，问题在面层。

## 4. 建议的下一步（只是建议，未实施）

按"人工成本最大的先做"的顺序：

1. **面层碎片。** 先量化碎片来源（多大的面、在哪里、是噪声还是线下推断），再考虑一个保守的处理，例如把小于几个像素、且被同一颜色类包围的面并入邻面。这一步可能误删真实的小细节，需要先在合成图上用 G1–G3 检查它不损失边界。
2. **面层边界损失**（量化 / 合并导致的色带和填色边界消失）。等第 1 步之后再做，需要先区分是 32 色量化还是 dE < 10 合并造成的。
3. 淡橙色细线和"线转面"工具属于后续，不急。

## 5. 限制

- 代理成本的权重是人为设定的，只能用于方案之间的相对比较，不能当作用户用时。QGIS 中的实际操作：`NOT_VERIFIED`。
- 面的合并次数是逐个操作的上界，批量融合的效果没有测。
- u2 只有部分参考：没有面的真值，不评价面操作；没描的文字和符号不计入。
- 合成数据由我们自己的生成器产生，真实地图的碎片分布可能不同。
- 这是对已有输出的回顾性评价，不是独立测试。
