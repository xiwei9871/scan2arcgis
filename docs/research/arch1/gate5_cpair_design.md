## 1. 准入判定：**有条件准入**

| 预注册条件 | 结果 | 满足 |
|---|---|---|
| O_NARROW_CANDIDATES 使 3–6 px 的 Oracle A ≥ 0.65 | 训练图 1.00，暴露图 1.00（Oracle B 同为 1.00） | ✓ |
| 区域数 ≤ 只用 B2 时的 3 倍 | 分级细分中位 1.60 倍，最大 2.21 倍 | ✓ |
| T1 中至少一个特征在两组图上 AUC ≥ 0.80，且与 B2 的错误 φ < 0.3 | 颜色差 0.841 / 0.838（φ 0.261）；宽度 0.844 / 0.824（φ 0.177） | ✓ |

三项都满足，按预注册 **C-PAIR V0.1 准入**。但 Gate 2–4 同时揭示了三个约束，V0.1 必须遵守，所以称为"有条件"：

1. **只给候选不够。** 完美窄候选在冻结合并下仍有 34–88% 被吞并，合并后 ≤ 6 px 召回只有 0.48 / 0.44。V0.1 必须同时带有保护机制，否则收益会被合并抵消（Gate 2、4）。
2. **还没有能当硬切割的证据。** 预注册要求误保护率 ≤ 0.10，而最好的单项证据在保留 95% 真实单元时误报率是 49–66%（Gate 1）。所以 V0.1 只能做**软保护**。
3. **局部线宽不能作为判别证据**（Gate 3 未通过）。区分墨带和窄地层要靠 B2 边界强度、颜色差、宽度三项相互独立的证据组合。

## 2. C-PAIR V0.1 设计

### 输入（全部来自预测和图像）
- B2 的像素对边概率 `prob_right`、`prob_down`
- 由 B2 边概率构建的线图：骨架、局部方向（结构张量）、端点、交点
- RGB → Lab；墨线掩膜（black-hat，只用于计算颜色时排除墨线像素）
- 现有 B2 过分割（C-RAG）和冻结的 RAG 合并

### 候选生成
1. **线段对：** 在线图上，对每条线段沿法线方向 2–12 px 范围内搜索另一条线段；要求局部方向差 ≤ 25°，并沿走向至少重叠 15 px。按局部方向逐段测间距，允许弯曲。
2. **缺口：** 同一条线上不超过 4 px 的缺口视为连续（B2 在 1 px 范围内的定位误差见 Gate 0：严格位置覆盖明显低于 1 px 容差）。
3. **尖灭：** 允许线对在一端汇合（间距降到 < 2 px）或一端开口，候选在汇合点截止。
4. **窄带掩膜：** 两条线之间的像素；去掉与已有 B2 过分割边界 1 px 内重合的部分（Gate 4 的去重规则）。

### 每个候选的证据（只用 Gate 1 证明有效且相互独立的三项）

| 证据 | 证据组 | 计算方式 |
|---|---|---|
| 两侧边界强度 | E-LINE | 两条线上 B2 边概率的中位数，取较弱一侧 |
| 颜色差 | E-APP | 窄带中线 ±1 px 的非墨线像素平均 Lab 色差，与两侧邻居分别计算，取较小值 |
| 预测宽度 | E-GEO | 线对间距的中位数 |

不使用：邻居数（Gate 1 过拟合）、局部线宽（Gate 3 未通过）；M1、M2 与 B2 高度相关，不重复计分。

### 决策状态与合并接口
- 所有候选先写入决策记录（`arch1_decision_store.py`，Gate 4 已验证几何可以逐像素还原），初始状态为 UNCERTAIN。
- 三项证据都指向"真实窄层"（三个独立组一致）时，状态为 **PROTECT（软）**：候选边界加入细分；合并代价加一个保护项 λ_p，使它比普通边更难被合并，但不设硬禁止。
- 颜色差和宽度两项独立证据都指向"墨带"时，状态为 **MERGE**：候选不加入细分，只保留在决策记录中。
- 其余情况为 **UNCERTAIN**：候选边界加入细分，正常参与合并；如果被合并，在 GIS 中输出为需复核对象。
- 三项证据的阈值和 λ_p 只在训练图上确定；按 Gate 1 的教训，每项证据只用一个阈值。

### 输出
候选掩膜、间距序列、三项证据及所属组、决策状态与原因、最终去向（存活或被并入哪个区域）。GIS 导出新增 `decision_state` 和 `evidence` 字段；被合并的 UNCERTAIN 候选作为单独的复核图层输出。

## 3. 下一阶段（阶段二）的预注册建议

- **只在训练图和已暴露图上开发和选参数。** 测试池不动。
- **门槛（阶段二结束时，在训练图和已暴露图上衡量）：**
  1. 3–6 px 的初始区域 Oracle A 从 0.45 / 0.64 提高到 ≥ 0.65（两组图都要），同时报告 Oracle B。
  2. 区域数 ≤ 只用 B2 时的 3 倍。
  3. **合并后**的 3–6 px 召回比 RAG_BOUNDARY_ONLY 提高 ≥ 0.10（两组图都要）。这是新增的门槛，防止只抬高 Oracle 上限、实际召回却被合并吃掉（Gate 2 的教训）。
  4. 被保护的候选中，属于墨带的比例（误保护）≤ 0.30，并且要报告。
  5. 没有灾难性合并；总召回不低于 RAG_BOUNDARY_ONLY − 0.01。
- **不通过时：** 报告是候选生成失败（Oracle A 没上去），还是保护失败（Oracle A 上去了但合并后没有），不在阶段二内反复调整。

## 4. 风险

| 风险 | 来源 | 缓解 |
|---|---|---|
| 墨带被误保护 | 宽度 < 6 px 的区域中，伪碎片与真实单元约 7.5:1 到 12:1 | 只有三项独立证据一致才保护；软保护；报告误保护率 |
| 软保护力度不够，候选仍被吞并 | Gate 2、4：冻结合并吞掉 34–88% | λ_p 在训练图上选；门槛 3 直接衡量合并后召回 |
| 线图质量差 | 严格位置下只有 7–18% 的窄实例两侧都被 B2 覆盖（Gate 0） | 允许 4 px 缺口、1 px 位置偏差；报告候选检出率 |
| 训练图窄层样本少（44 个） | 阈值不稳 | 每项证据只用一个阈值；暴露图上（160 个）检查方向 |
| 在中国图上失效 | B2 在中国图上 41–58% 响应纹理 | 颜色差在当前图幅内计算，不依赖色表；中国图需要人工真值 |
