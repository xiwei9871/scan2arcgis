# 06 推荐路线、MVP 定义与阶段计划

推荐路线：**路线 B（保留可用模块，替换薄弱环节）**，但前提是先完成 M0 和 M1 的数据与可行性验证。总体建议见 08 文档：`RESEARCH_FIRST`，之后进入 `PARTIAL_REBUILD`。

工作量用"人周"表示相对量级，假设 1 名开发 + 1 名地质标注/验收人员。这些数字是规划假设，不是承诺。

## 1. MVP 定义

**MVP = 一张真实地质图，在人工录入图例和人工确认四角坐标后，输出可在 QGIS 中正确叠加的 GeoPackage/Shapefile，包含：地层与侵入岩多边形（带图例代号）、由面拓扑导出的接触界线。断层和矿种点由人工在复核界面中补充或确认。**

明确不在 MVP 内：等高线、全自动独立线要素识别、全自动矿种识别、ML 训练与模型发布、MoE、无图例识别、多用户与服务器部署。

## 3. 里程碑

### M0：事实调查与技术路线确定（本次审计 + 1–2 人周）

- 目标：确认业务需求和数据现实。
- 任务：(1) 与业务方确认要素范围、精度要求、交付格式、目标客户的 GIS 软件；(2) 收集 20–30 张真实图幅（不同比例尺、扫描质量、年代），记录来源与授权；(3) 让 CI 跑起来：修复 `msvcrt` 与 `matplotlib`，在 Linux 上运行测试，记录失败数；(4) 本审计评审。
- 前置条件：项目负责人批准范围。
- 产物：书面 MVP 范围、数据清单、CI 首次运行报告。
- 验收：范围文档签字；至少 20 张图到位；CI 能出具测试报告（不要求全绿）。
- 风险：拿不到真实客户数据。
- 备选：用公开的中国地质图样张加 USGS AI4CMA 数据先做方法验证，但不能据此宣告交付。
- Go/No-Go：拿不到 ≥10 张有代表性的真实图幅 → **No-Go**，停在数据收集，不写算法代码。

### M1：核心技术可行性验证（3–5 人周）

- 目标：用客观指标证明面要素提取和地理坐标输出能达到业务可接受水平。
- 任务：(1) 按 07 文档标注 10 张图的全幅面要素（至少验证集 5 张不参与调参）；(2) 把当前面识别作为基线跑一次，得到真实 mIoU 与图例绑定准确率；(3) 实现"GDAL 配准 + 像素坐标转地理坐标 + OGR 导出"最小链路，用独立检查点测位置误差；(4) 至少尝试一种外部方法（如 SAM 交互分割或 LOAM 类方法）作对比；(5) 测量单张图人工复核耗时。
- 前置条件：M0 Go。
- 产物：评估脚本与报告（可复现）、地理位置误差报告、方法对比表。
- 验收标准（门槛由 M0 中业务方确认，以下为待确认的建议形式）：验证集面要素 mIoU ≥ 业务确认值；图例绑定准确率 ≥ 业务确认值；检查点位置误差 ≤ 业务确认值（与比例尺相关，例如 1:5 万图上的图面误差限）；人工修正耗时 < 纯人工数字化耗时的业务确认比例。
- 风险：面要素在多种图幅上远低于门槛。
- 备选：转路线 C 的"交互式半自动"——用户点选面，系统分割，比全自动更可靠。
- Go/No-Go：若人工修正耗时 ≥ 纯人工数字化耗时，说明自动识别没有价值 → **No-Go**，转为纯工具型产品（配准 + 人工数字化辅助）或停止。

### M2：最小完整业务闭环（3–5 人周）

- 目标：一个用户能在 Web 界面中完成 MVP 定义的全流程。
- 任务：把 M1 的链路接入现有上传、预处理、图例录入、复核 UI；界线由面拓扑导出；断层与矿种提供人工描线/点选与吸附；导出 GeoPackage 与 Shapefile，带 CRS 和属性。
- 产物：可安装版本（Windows 安装说明 + Linux Docker），端到端验收报告。
- 验收：3 张未参与开发的图由非开发人员独立完成，输出在 QGIS 中叠加检查通过；端到端测试在 CI 中运行。
- 风险：现有前端与 API 耦合重，接入成本超出预期。
- 备选：先交付命令行 + QGIS 插件版本。
- Go/No-Go：非开发人员不能独立完成 → 先修流程，不进入 M3。

### M3：稳定性与兼容性（4–8 人周）

- 目标：扩大到 30 张以上图幅，处理边界情况。
- 任务：大图分块（Rasterio 窗口读取），处理劣质扫描、缺图例、跨图幅；如数据支持，再评估矿种自动候选与独立线要素候选。
- 验收：失败率、平均耗时、人工修正耗时在 30 张图上达到 M0 设定的门槛。
- Go/No-Go：任何新增自动化功能必须在评估集上证明降低人工修正耗时，否则不并入。

### M4：工程化与交付（3–6 人周）

- 目标：可交付客户。
- 任务：日志、错误处理、安装包、用户文档、权限、数据备份；视需要再做多用户。
- 验收：客户环境试装；用户手册；回归测试全绿。

## 4. 如果只允许解决三个问题

1. **建立真实评估集和验收门槛**（M0/M1）。没有它，任何算法改进都无法判断，项目会继续在补丁循环中打转。这是所有其他工作的前提。
2. **打通并验证地理坐标输出链路**（GDAL 配准 → 坐标变换 → OGR 导出 → QGIS 叠加）。这是"转成 GIS 可读格式"的业务本身，目前没有任何证据证明它正确。
3. **确定线要素和点要素的半自动边界**，把接触界线改为由面拓扑导出，断层和矿种改为"候选 + 人工确认"。这能停止最大的开发量黑洞（界线规则调参），并给出可交付的质量保证方式。

修复 245 个失败测试不在前三位：它们大多是过期测试，修复它们不改变任何结果的正确性。但应在 M0 中顺带让 CI 跑起来。
