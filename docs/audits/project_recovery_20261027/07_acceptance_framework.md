# 07 真实测试数据、指标与验收方法

| 数据 | 位置 | 内容 | 能否用于验收 |
|---|---|---|---|
| 地质图1 | `docs/地质图1.jpg` | 19011×20604，300 dpi | 能，但需全幅标注 |

| 地质图2 副本 | `docs/地质图2 - 副本.jpg` | 2752×5330，96 dpi（裁剪/降采样） | 只能作"低分辨率"边界案例 |

**数据缺口**：(1) 只有 2 张完整图，来源与授权未记录；(2) 没有全幅标注；(3) 没有配准真值（检查点的真实坐标）；(4) 没有人工数字化耗时基准；(5) 不知道客户实际图幅的分布。

## 2. 数据获取要求

- 数量：M1 至少 10 张（开发 5 / 验证 5），M3 至少 30 张。
- 覆盖：至少 2 种比例尺；新旧图式各有；扫描质量好/差各有；包含近色地层、密集断层、图例不完整、跨图幅接边各至少 1 张。
- 每张图需记录：来源、比例尺、坐标系、图幅号、扫描分辨率、使用授权。
- 客户资料与涉密图件不得入库，只记录哈希与元数据，图像存放在受控位置。

## 3. 标注规范（最小可行）

- 面要素：全幅多边形，属性为图例代号；用 QGIS 在配准后的图上标注，保存为 GeoPackage。
- 线要素：接触界线可由面标注自动导出；断层单独描线，属性为类型。
- 点要素：矿种点位 + 矿种代号。
- 配准真值：每张图至少 8 个独立检查点（图廓角点之外的经纬网交点或公里网交点），不参与配准计算。
- 标注由地质人员完成，另一人抽查 10%。

## 4. 指标

| 维度 | 指标 | 计算方法 | 门槛来源 |
|---|---|---|---|
| 面要素正确率 | 按图例类别的 mIoU；面积加权准确率 | 像素级比较 | M0 业务确认 |
| 图例绑定 | 绑定准确率 | 正确代号的面数 / 总面数 | M0 业务确认 |
| 接触界线 | 缓冲区 F1（容差按比例尺换算为图上 mm） | 预测线与真值线缓冲区重叠 | M0 业务确认 |
| 断层 / 矿种 | F1（距离容差） | 匹配后计数 | M3 再定，MVP 中由人工保证 |
| 地理位置误差 | 检查点误差的 RMSE 与最大值（米及图上 mm） | 留出检查点 | 按比例尺制图精度规范，由业务方确定 |
| 拓扑质量 | 面无重叠、无缝隙比例；线闭合率 | GEOS 检查 | 0 重叠为硬性要求 |
| 格式兼容 | QGIS 与 ArcGIS 能打开、CRS 正确、属性中文不乱码 | 人工 + 自动脚本 | 100% |
| 自动化比例 | 无需修改的要素占比 | 复核记录 | 记录即可 |
| 人工修正工作量 | 每张图复核时长；与纯人工数字化时长之比 | 计时 | 核心 Go/No-Go 指标 |
| 处理耗时 | 单张图从上传到可复核的时间 | 日志 | M0 确认 |
| 失败率 | 无法完成流程的图幅比例 | 批量运行 | M3 确认 |
| 鲁棒性 | 上述指标按图幅类别分组 | 分组统计 | 最差组不低于业务下限 |

本审计**不设定具体阈值数字**，因为没有业务需求依据。门槛必须在 M0 由业务方确认。现有 `minimum_metrics.json` 中的阈值（如界线 F1 ≥ 0.12）是防退步线，不能作为交付门槛。

## 5. 最小验证集结构

| 类别 | 用途 | 现有候选 | 缺口 |
|---|---|---|---|
| 常规成功案例 | 证明主流程 | 地质图2 | 再需 3–4 张 |
| 已知失败案例 | 防止回退，测量改进 | 地质图1 中的近色地层、经纬网、图框区域（manifest 中已有 ROI） | 需全幅标注 |
| 极端边界案例 | 大图性能 | 地质图1（3.9 亿像素） | — |
| 低质量输入 | 鲁棒性 | 地质图2 副本（96 dpi） | 需真实劣质扫描 |
| 输入不完整 | 缺图例、缺角点注记 | 无 | 需收集 |
| 特殊格式 | PDF、TIFF、多页 | 无 | 需收集 |

每个案例保存：输入哈希、图例录入 JSON、预期输出（GeoPackage）、实际输出、评估报告 JSON、运行环境。评估脚本应能一条命令复现。

## 6. 验收方法

1. 评估脚本独立于识别代码，只读输入输出文件。
2. 验证集图幅在开发期间不得用于调参；每次调参只能看开发集。
3. 每个里程碑的报告必须包含：数据清单、指标表、与上一版本对比、失败案例截图。
4. 人工修正耗时由非开发人员计时。
5. 任何"通过"结论必须指明对应的门槛来源。
