## 4. 重复失败分析

### 4.1 地质界线：同一问题换实现，始终未达可用

[VERIFIED] 33 个提交修改过 `backend/core/recognition/boundary`，提交信息中出现"误检"14 次、"误识别"7 次、"漏检"5 次、"偏移"4 次、"误杀"2 次。按时间看，同一类问题反复出现：

| 问题 | 出现的提交 |
|---|---|
| 图框、经纬网、格网被识别为界线 | `4551a4c`(04-09)、`d769b02`(05-15)、`24976d4`(08-12)、`953b405`(10-21)、`33e5f7b`(10-23) |
| 近色地层间界线漏检 | `ba5e188`(05-22)、`7f07435`(10-19)、`33e5f7b`(10-23) |
| 断点之间凭空连线 / 碎段 | `d7f33b8`(04-09)、`b3ca787`(08-10)、`7f07435`(10-19) |
| 原图与分析图坐标换算偏移 | `4f7893e`(09-19，矿点)、`d5d771a`(10-22，界线) |

baseline 上的地质界线 `buffer_f1` 为 0.1222（门槛 0.12），从 05-27 之后再无新的评估入库，所以 6 月到 10 月共约 20 个界线提交**没有任何客观指标证明其改进**。[VERIFIED, E13]

[INFERRED] 这是"同一个问题换不同实现方式但始终没有真正解决"的典型情况。每一轮改动都由人工看图发现的具体误检/漏检驱动，然后加规则或阈值；`boundary` 目录中 1,410 个浮点字面量是这种模式的累积结果。

### 4.2 指标门槛被设在当前结果附近

[VERIFIED, E13] `evaluations/recognition_baseline_v1/minimum_metrics.json` 中的门槛在 `1dd78f3`（05-11）首次设定：界线 `buffer_f1 >= 0.12`，等高线 `buffer_f1 >= 0.1`，`elevation_accuracy >= 0.05`，地层 `miou >= 0.2`。实际结果：界线 0.1222，地层 0.3813，等高线高程 0.0（该项设为可选，所以总体仍判 PASS）。

[INFERRED] 门槛的作用是"防止退步"，不是"达到可用"。但 `gates.overall.threshold_pass = True` 容易被误读为"质量通过"。

### 4.3 字段契约反复迁移，测试跟不上

[VERIFIED, E10] 当前 245 个失败测试中，排前几位的失败签名全部是改名或结构调整：`symbol_shape_id`（55+18+5 处）、`section_id`（24+18+4 处）、`contour_pipeline` 属性已删除（15 处）、`OCRRegion.region_id`（7 处）。这些字段是在 `caa44b5`(10-13)、`c133723`(09-30)、`1d8828a`(10-16) 中改掉的。

[INFERRED] 测试失败主要是"测试过期"而不是"功能回归"，但这同时说明项目没有"测试不通过就不能提交"的约束，测试套件已经不能作为回归保护。

### 4.4 范围持续扩张

[VERIFIED] 原设计 4 个功能，1 个月 MVP。后续新增：侵入岩（06-30）、矿种（07-03）、机器学习样本库与训练（08-17）、MoE 专家（09-12）、难例池（10-01）、地质构造（10-16）、跨任务全局 ML 资产（10-19）。同期，原始核心功能之一（等高线）被停用，另一核心功能（界线）仍未达标。

[INFERRED] 存在需求漂移：新功能的加入不以既有功能达标为前提。

### 4.5 UI 打磨占比高

[VERIFIED] 3 月的 46 个提交中，大部分是配准界面交互细节（红点闪烁半径、左右键拖拽、确认弹窗、布局调整）。后期大提交中，UI 文案、按钮颜色、高亮节奏也占很大比例（如 `c133723` 第 25–34 项、`b31953a` 第 8–16 项）。
